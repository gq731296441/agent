# 新建邮件（参考）

本参考描述**新建邮件**（不涉及草稿箱）的完整流程：参数解析、收件人/抄送人搜索与同名确认、**展示邮件信息并等待用户确认**、用户确认后再调用脚本发送与输出格式。一律使用 main.py send **立即发送**。若用户提到**具体发送时间**（如「明天 9 点」「下午 3 点发」），流程见 [draft_box.md](draft_box.md) 场景七：新建邮件预约发送。

**前置与相关文档**：收件人为「我」时，须先按 **[me.md](me.md)** 执行 `main.py my-info` 获取当前用户完整信息（返回的 `user` 与 search-users 用户项一致），用该信息代表「我」。涉及「今天」「明天」等相对时间时，须按 **[time.md](time.md)** 先执行 `main.py get-time` 再解析。脚本报错、群组无权限、展示规则等**错误与重试**见 [scripts_and_errors.md](scripts_and_errors.md)。

**强制要求（不可违反）**：**发邮件必须先向用户展示当前邮件信息**（收件人、标题、正文等）。**若用户明确表示希望直接发送**（如「直接发」「不用确认」「发吧别问了」等），可**省去确认步骤**，展示后直接调用发送脚本；否则须**等用户明确确认**（如回复「确认发送」「发送」「发吧」）后才能调用。步骤 3（展示）**不可跳过**；步骤 4（调用发送）可在用户已明确回复确认发送**或**用户意图可识别为「直接发送」时执行。收件人唯一匹配时也**必须**先展示。

**强硬要求（群组无权限）**：发送时若某**群组**没有权限（如后端返回「用户没有权限使用邮件组」等），**不得自行改选其他群组**，必须直接向用户提示「xx 群组没有权限」或展示脚本/后端返回的 error 原文，由用户决定是否更换收件人。

**强硬要求（展示须严格依据 search-users 返回）**：展示用户/群组信息时，**必须严格按照 [search-users](search-users.md) 返回的数据**进行展示（姓名取 N、工号取 UNO、部门取 T、群组名取 N、邮箱取 E 等），**禁止臆断、猜测、编造**任何未在返回中出现的字段或内容；若某字段返回为空则展示为空，不得自行补全或替换为其他来源。

**展示信息时的发件人/收件人/抄送人规则**（发邮件确认、查看邮件、回复预览等场景均适用）：**优先使用姓名+工号，没有时再使用邮件地址**。
- **人（通讯录用户）**：优先 **姓名+工号**，如「谢飞武（0668001367）」；姓名与工号来自 search-users 返回的 **N**、**UNO**。若 N、UNO 均无，再用 **E**（邮件地址）展示。
- **邮箱地址**：当无姓名、工号时，直接使用邮箱地址展示，如 `xxx@example.com`；**须来自**返回的 **E** 或用户输入的邮箱。
- **群组**：只显示群组名字，**须来自**返回的 **N**；不加工号。

## 场景六：新建邮件

### 触发条件

用户输入中包含发邮件意图 + 收件人 + 邮件内容，**不涉及草稿箱**；或用户说「给xxx发邮件」。一律立即发送（main.py send）。

### 参数

| 要素     | 是否必填 | 说明 |
| -------- | -------- | ---- |
| 收件人   | 选填     | 收件人、抄送人、密送人**不能同时为空**，至少填一项。主送对象，多人用逗号分隔；支持**用户**（姓名/工号）、**群组**（群组名/关键字）或**邮箱地址**（如 user@example.com）。收件人为「我」时按 **[me.md](me.md)** 先调用 `main.py my-info` 获取当前用户完整信息，用返回的 `user` 代表「我」参与发送（无需再对「我」调用 search-users）。 |
| 邮件标题 | 可选     | 未提供则传空字符串 |
| 邮件内容 | 可选     | 正文；未提供时传空字符串即可。**支持 Markdown** 字符串（见下方「邮件正文 Markdown 支持」）。 |
| 抄送人   | 可选     | 抄送对象，多人用逗号分隔；支持用户（姓名/工号）、群组（群组名/关键字）或邮箱地址 |
| 密送人   | 可选     | 密送对象，多人用逗号分隔；支持用户、群组或邮箱地址，与抄送解析逻辑一致。**展示确认邮件信息及发送成功反馈时需展示密送人**。 |
| 附件     | 可选     | 本地文件路径，多个用逗号分隔。**路径须为符合 Windows 与 Linux 的绝对或相对路径**，如 `/home/work/1.txt`、`C:\Users\work\1.txt`。脚本会校验文件存在性、总大小（≤30MB）、可读权限。 |
| 图片插入正文 | 可选  | **CLI 入参**：`--is-inline`，取值仅 `"0"` \| `"1"`，默认 `"0"`。`"1"` 时尝试将**图片**附件插入正文显示；非图片仍为普通附件。**子命令**：`send`、`create-draft` 支持；`save-draft` 仅当**未传 `--draft`**（新建草稿）时可用，与 `--draft` 联用时**不得**使用非默认的 `--is-inline`。预约发送用 `create-draft`，见 [draft_box.md](draft_box.md) 场景七。 |

#### 附件路径识别规则

- **路径为文件**：直接作为附件，无需向用户确认。
- **路径为文件夹**：仅列出该文件夹**第一层级下的所有文件路径（不递归子目录）**，向用户展示列表，**等用户确认**后再将确认后的路径传入 `--attachments`。若用户未确认或要求修改，不得直接发送；如需发送子目录文件，应由用户明确指定具体子目录或文件路径后再处理。

#### 邮件正文 Markdown 支持

正文可传 **Markdown 字符串**；常见语法包括：**粗体**、*斜体*、列表、换行、标题、链接、图片；**表格**（`| 列1 | 列2 |`）；**脚注**（`[^1]` 与文末 `[^1]: 说明`）。展示效果以 zMail 中实际渲染为准。

### 步骤1：解析用户查询

从用户输入中提取：

```yaml
query_params:
  title: "邮件标题"
  to: "收件人1,收件人2"     # 多人用逗号分隔
  cc: "抄送人1,抄送人2"     # 可选，多人用逗号分隔
  bcc: "密送人1,密送人2"    # 可选，多人用逗号分隔
  body: "邮件正文内容"
  attachments: "path1,path2"  # 可选；路径为文件则直接使用，为文件夹则需先列出该目录下所有文件路径供用户确认后再传入
  is_inline: "0"            # 可选；用户明确要把图片插入正文且 attachments 含图片路径时置 "1"，否则 "0" 或省略；步骤 4 拼 send、create-draft 或 save-draft（无 --draft）时映射为 --is-inline
```

**收件人为「我」**：按 **[me.md](me.md)** 执行，先调用 `python3 {baseDir}/scripts/main.py my-info` 获取当前用户完整信息；将返回的 `user`（UNO/N/E/T）作为「我」的代表，**步骤 4 传 `--to` 时须使用 `user.E`（邮箱）**；展示步骤仍可用姓名+工号。若 my-info 返回为空或失败，提示用户「无法获取当前用户信息，请检查环境或指定收件人」。

#### 参数缺失处理

- **收件人、抄送人、密送人不能同时为空时**：提示用户至少填写收件人、抄送人或密送人之一。
- **邮件标题**：可选，未提供时传空字符串。
- **邮件内容**：可选，未提供时传空字符串即可，无需向用户确认。
- **`is_inline`**：未提及把图片插入正文时视为 `"0"`；仅当用户明确要把附件中的图片插入正文且存在 `attachments` 时置 `"1"`。

### 步骤2：解析收件人（先确认再发送）

收件人解析按 [search-users.md](search-users.md) 的定义处理。

确认收件人后进入步骤 3 展示邮件信息，用户确认后再调用 main.py send。

### 步骤3：展示邮件信息并等待用户确认

**（再次强调）发邮件必须先展示才能发送。** 在真正调用发送脚本之前，必须先向用户展示当前邮件信息（标题、收件人、抄送、密送、附件、正文；若用户提到具体发送时间则含该时间），支持用户修改。**若用户明确表示「直接发」「不用确认」等希望无需确认即发送**，展示后可直接进入步骤 4；否则须**等用户明确确认后再发送**，未展示或未收到用户确认前**不得**调用 main.py send / main.py create-draft。

**重要**：**仅当用户明确表达发送意图或意图可识别为「直接发送」时才能进入步骤 4 调用脚本**。用户仅提出修改（如「标题改成 XXX」「正文加点祝福」）时，只更新参数并重新展示邮件信息，**不得发送**；必须等用户回复「确认发送」「发送」「发吧」等确认语，或用户已表达直接发送意图后，再调用 main.py send。

#### 3.1 输出当前邮件信息

将以下内容**完整展示**给用户（标题、收件人、抄送、密送、附件、正文；若用户提到具体发送时间则包含该时间）：

**收件人、抄送人、密送人展示规则**：按类型区分——**人（通讯录用户）**：优先姓名+工号，如「谢飞武（0668001367）」；无姓名或工号时用邮箱地址；**群组**：只显示群组名字。多人用分号分隔。有抄送/密送时按上述规则展示；抄送/密送为空时不展示对应行。

**标题、正文展示规则**：没有数据就留空白，不显示任何内容（不显示「空」「（无标题）」「（无正文）」等）。

**附件展示规则**：有附件时在邮件信息中展示附件路径列表（路径已含文件名）。若用户给出的路径为**文件夹**，须先列出该文件夹下所有文件的完整路径供用户确认，用户确认后再将路径列表纳入展示；**路径为文件**则直接展示，无需额外确认。

**用户提到具体发送时间**时展示格式（含发送时间一行）：

```
请确认以下邮件信息，确认无误后回复「**确认发送**」即可发出；如需修改，请直接说明要改的内容（如「标题改成 XXX」「收件人加上 XXX」）。

- **密送**：{bcc}（有密送时同上规则：人优先姓名+工号，无时用邮箱；群组=名字；无密送时省略此行）
```

- 展示时 **to/cc/bcc** 的取值：**人**优先「姓名（工号）」，无姓名或工号时用邮箱地址；**群组**只显示名字；**名字、工号、群组名必须全部来自 search-users 的返回（N、UNO、E 等），不得臆断、猜测或编造。**
- **保存当前邮件参数到对话上下文**：title、**to/cc/bcc（均为邮箱字符串，对应命令行三参数）**、body、**attachments**（确认后的附件路径列表）、at。**此处 to/cc/bcc 必须是步骤 2 用户确认后的邮箱，不是用户最初输入的姓名/关键字。** 步骤 4 调用发送时**只从该上下文读取这些值**，禁止在发送时再次执行 search-users 或将姓名/群组名直接写入命令行。

#### 3.2 用户回复处理

| 用户回复类型 | 处理方式 |
| ------------ | -------- |
| **确认发送** | 用户说「确认」「确认发送」「发送」「发吧」「可以发了」「就发这个」等**明确发送意图** → 进入步骤 4 调用脚本发送，**不再再次展示**。**用户明确表示「直接发」「不用确认」等希望无需确认即发送**时，展示后也可直接进入步骤 4。 |
| **提出修改** | 用户仅说明要改的内容（如「标题改成 会议通知」「收件人加上 李浩」「正文改成 xxx」「内容多点祝福」）→ 见下方「修改时的处理规则」更新参数后，**仅再次执行步骤 3.1** 展示更新后的邮件信息，**不调用发送脚本**，再次等待用户确认。可多轮修改，直到用户**明确说确认发送/发送/发吧等**后才可发送。 |
| **取消发送** | 用户说「不发了」「取消」「算了」等 → 终止流程，不调用发送脚本。 |

**修改时的处理规则：**

- **仅改标题、正文、发送时间**：根据用户表述直接更新对应字段，未提到的字段保持当前值。
- **任何涉及收件人/抄送人/密送人的修改**（如「收件人改成 王伟」「抄送加上 李浩」「密送加上 张三」）：**必须先查人/查群组**，与步骤 2 相同流程：
  1. 对本次修改中涉及的**新人名/群组关键字**调用 `main.py search-users`（或与步骤 2 相同的查人/群组逻辑）进行解析。
  2. **唯一匹配**：若该关键字只匹配到 1 个用户或 1 个群组，则用该用户或群组的**邮箱 E** 更新 to/cc/bcc 或 to_group/cc_group/bcc_group，再执行步骤 3.1 展示。
  3. **多人/多群组匹配**：若该关键字匹配到多位用户或多个群组，**必须展示列表**（用户：序号、姓名、工号、部门；群组：序号、群组名、部门/描述），请用户选择（用户如「第 1 个」或「工号 xxx」，群组如「第 1 个」或群组名）；**禁止**自行选择，等用户确认后再用选中项的**邮箱 E** 更新对应字段，再执行步骤 3.1 展示。
  4. **未匹配**：若 `no_match_keys`（或群组的 `no_match_cc_keys` / `no_match_bcc_keys`）包含该关键字，提示未找到匹配用户/群组，请用户确认姓名、工号或群组名，不更新 to/cc/bcc，不发送。
- 调用 send/create-draft 时，**`--to` / `--cc` / `--bcc` 须为步骤 2 确认后的邮箱（逗号分隔）**，不得传入姓名等关键字；**不在发送步骤中再按关键字搜索收件人**。
- 若用户只说了修改内容但未说「确认发送」，展示更新后的信息后再次提示「请回复「确认发送」发送，或继续说明需要修改的内容。」**此时不得调用 main.py send / main.py create-draft**，必须等待用户下一次明确表示发送意图后再发送。

### 步骤4：调用脚本发送邮件（仅用户确认发送后执行）

**前置条件（不满足则禁止执行本步骤）**：必须已完成步骤 3 并向用户展示邮件信息，且用户已明确回复「确认发送」「发送」「发吧」等发送意图**或**用户意图可识别为「直接发送」；**未展示或未获用户确认前不得调用 main.py send**（用户未表达直接发送意图时）。

**约定**：发送时传入的**收件人、抄送人、密送、群组邮箱均来自 search-users 确认后的邮箱**。使用 **`--to` / `--cc` / `--bcc`** 三个参数（逗号分隔邮箱，群组可与个人混在同一参数）；不做收件人搜索；**每个邮箱会校验并解析收件人信息**，任一失败则整单报错。详见 [cli-to-cc-bcc.md](cli-to-cc-bcc.md)。

**强制要求（防止重复/错发）**：

- **上述参数必须来自步骤 2～3 已写入上下文的「已确认邮箱」**，不得在步骤 4 根据用户原始输入或当前回复重新解析。
- **禁止在步骤 4 再次执行 search-users**；禁止将用户输入的姓名、群组名等关键字直接写入命令行；若上下文无已确认的邮箱列表，应提示用户先完成步骤 2 的收件人确认再发送。
- 这样可避免「发送时再次按关键字搜索」导致一名多匹配、重复发送或错发。

**根据是否识别出具体发送时间选择脚本**：

- **已解析出具体发送时间**（YYYY-MM-DD HH:MM）→ 调用 `main.py create-draft`（必须传 `--at`）
- **用户仅说「定时」「定时邮件」等、未给出具体时刻** → **不算提到具体发送时间**，**一律立即发送**，调用 `main.py send`（不询问时间）
- **用户说出了可识别的时间表述但无法解析为具体时刻**（如「明天某个时候」）→ 先询问用户确认具体发送时间，待用户补充后再解析并走 create-draft
- **未识别出用户提及具体发送时间**（未提及、或用户明确不指定时间）→ **一律立即发送**，调用 `main.py send`

**发送使用 `--to` / `--cc` / `--bcc`**：均为逗号分隔邮箱；群组邮箱可与个人邮箱写在同一参数中。脚本校验邮箱格式并解析收件人信息后，失败则报错。完整约定见 [cli-to-cc-bcc.md](cli-to-cc-bcc.md)。

### 命令行示例

```bash
python3 {baseDir}/scripts/main.py create-draft \
  --title "标题" \
  --to "zhang.san@example.com" \
  --cc "cc@example.com" \
  --bcc "" \
  --body "邮件正文" \
  --at "YYYY-MM-DD HH:MM"
```

有附件时追加 `--attachments`（多个路径逗号分隔，路径须兼容 Windows/Linux，如 `/home/work/1.txt`）：

```bash
python3 {baseDir}/scripts/main.py send --title "标题" --to "a@example.com,b@example.com" --body "正文" --attachments "/home/work/1.txt,/home/work/2.pdf"
```

**`--is-inline`（拼命令约束：是否把图片插入正文，供模型执行）**

| 条件 | 行为 |
|------|------|
| `attachments` 为空 | **不传** `--is-inline`（用 CLI 默认即可） |
| 需把图片插入正文 | 在已有 `--attachments` 上追加 `--is-inline "1"`；**仅图片**生效 |
| `save-draft` | **仅**未传 `--draft`（新建草稿）时可带 `--is-inline`；**与 `--draft` 联用时**不得使用非默认的 `--is-inline`，见 [draft_box.md](draft_box.md) 场景六 |

```bash
# send + 图片插入正文（与 create-draft / save-draft 参数名相同）
python3 {baseDir}/scripts/main.py send --title "标题" --resolved-recipients '...' --body "正文" --attachments "/home/work/a.png,/home/work/b.pdf" --is-inline "1"
python3 {baseDir}/scripts/main.py create-draft --title "标题" --to "a@example.com" --body "正文" --at "YYYY-MM-DD HH:MM" --attachments "/home/work/a.png" --is-inline "1"
python3 {baseDir}/scripts/main.py save-draft --title "标题" --body "正文" --attachments "/home/work/a.png" --is-inline "1"
```

- `--title`：邮件标题，可选。
- `--body`：正文，可选。
- `--attachments`：附件路径，多个用逗号分隔，可选。
- `--is-inline`：可选，`"0"` \| `"1"`，默认 `"0"`；语义见上表及参数表「图片插入正文」行。

**说明**：仅当用户在步骤 3 中明确表达发送意图（如「确认发送」「发送」「发吧」）后，才执行本步骤。邮箱须来自 search-users/my-info 确认，脚本解析并校验每个邮箱后发送。

### 步骤5：解析返回并输出

```json

  "mid": "邮件ID"

```

**强硬要求（群组无权限）**：若发送失败且 error 与某群组无权限相关（如「用户没有权限使用邮件组」），**禁止**自行改选其他群组或重试其他收件人；须直接向用户提示「xx 群组没有权限」或原文展示 error，由用户决定是否更换收件人。
