# search-users（收件人解析参考）

本参考描述 **search-users** 子命令的用途、调用方式、返回结构及处理规则。收件人/抄送人/密送人解析供 [send.md](send.md)、[draft_box.md](draft_box.md)、[forward.md](forward.md)、[reply.md](reply.md) 等使用。

**强硬要求（展示须严格依据 search-users 返回）**：展示用户/群组信息时，**必须严格按照 search-users 返回的数据**进行展示（姓名取 N、工号取 UNO、部门取 T、群组名取 N、邮箱取 E 等），**禁止臆断、猜测、编造**任何未在返回中出现的字段或内容；若某字段返回为空则展示为空，不得自行补全或替换为其他来源。并且当某关键字匹配到多个结果（`keywords_with_multiple` 非空）时，**必须、一定需要用户选择确认**，**禁止**自行选择任一项（包括但不限于取列表第一项/同部门等自动推断）。

---

## 用途

收件人/抄送人/密送人支持三类：

- **邮箱地址**：如 `user@example.com`，直接作为外部收件人，无需搜索
- **用户**：姓名/工号，如 `谢飞武`、`王伟`，需按**用户**搜索通讯录，同名时需用户确认
- **群组**：群组名或关键字，如 `项目组`、`zmail测试`，需按**群组**搜索；**若不能唯一匹配群组（某关键字匹配到多个群组），必须展示群组列表让用户选择**，与用户同名的处理方式一致

**密送（bcc）**：与抄送采用同样的 search-users 与同名处理逻辑，最终写入发送时的 **`--bcc`**（邮箱，可与主送/抄送同属确认结果）。展示确认邮件信息及发送成功反馈时**需展示密送人**。

---

## 命令

**识别规则**：**若能根据用户输入识别为群组**（如「项目组」「前端组」「zmail测试」等群组名/关键字），则对该关键字使用**群组**搜索；**否则按用户（查人）**搜索。邮箱地址不搜索，直接作为外部收件人。

- **仅用户**：识别为个人的收件人/抄送/密送
  ```bash
  python3 {baseDir}/scripts/main.py search-users --to "收件人1,收件人2" --cc "抄送人1,抄送人2" --bcc "密送人1"
  ```
- **仅群组**：识别为群组的收件人/抄送/密送
  ```bash
  python3 {baseDir}/scripts/main.py search-users --type group --to "群组1,群组2" --cc "抄送群组1" --bcc "密送群组1"
  ```
- **用户与群组混合**：to/cc/bcc 中既有识别为用户的也有识别为群组的，按关键字分别调用上述两种命令，合并结果后再做同名/多群组确认。

---

## 返回结构

### 用户搜索（`type` 为 `"user"`）

- `to_searches` / `cc_searches` / `bcc_searches`：每项 `{"keyword": "xx", "users": [{UNO, N, E, T}, ...]}`
- `keywords_with_multiple`：某关键字匹配到多位用户时
- `no_match_keys`：未匹配到用户的关键字

示例：

```json
{
  "status": true,
  "type": "user",
  "keywords_with_multiple": {
    "王伟": [
      {"UNO": "0668000589", "N": "王伟", "T": "办公自动化产品团队/..."},
      {"UNO": "10182695", "N": "王伟", "T": "网络优化部/..."}
    ]
  },
  "no_match_keys": []
}
```

### 群组搜索（`--type group`）

- `type`: `"group"`
- `to_group_searches` / `cc_group_searches` / `bcc_group_searches`：每项 `{"keyword": "xx", "groups": [{UNO, N, E, T}, ...]}`
- `keywords_with_multiple`：某关键字匹配到多个群组时，**群组仅用 N、T 标识**（无 UNO，个人才有 UNO），格式为 `[{N, T}, ...]`；**此时必须展示群组列表让用户选择**，不能唯一匹配则不可自动选定。
- `no_match_keys` / `no_match_cc_keys` / `no_match_bcc_keys`：未匹配到群组的关键字

群组多选时展示表格列为：序号、群组名（N）、部门/描述（T），无工号列；用户多选时仍为序号、姓名、工号、部门。

---

## 三种情况处理

### 情况 A：`keywords_with_multiple` 不为空（存在同名用户或多群组）

**不发送邮件**，向用户展示**所有**有歧义的关键字及其匹配列表（用户或群组），请用户**一次性确认**。

**关键**：`keywords_with_multiple` 中可能包含**多个关键字**（收件人/抄送人/密送人、用户/群组混合均可），必须将所有歧义关键字**一起展示**，让用户在一次回复中全部确认，而非逐个询问。**群组与用户一视同仁：若某关键字匹配到多个群组（不能唯一匹配），也必须展示群组列表**（序号、群组名（N）、部门/描述（T）），让用户选择后再继续，不得在未展示、未选择的情况下假定或自动取第一个。

**强制禁止（不可违反）**：当存在多名匹配（`keywords_with_multiple` 非空，含**同名用户**或**多群组**）时，**禁止**自行选择具体人员或群组（包括但不限于：同部门、同团队、列表第一项、工号、群组名等任何规则）。**必须**等待用户**明确指定**每个歧义关键字所对应的人选或群组（用户示例：「王伟选第 1 个」「胜贵用 0668000561」；群组示例：「项目组选第 1 个」）后，才能用选中的工号/群组名更新 to/cc 并进入后续流程；若用户仅回复「发送」「确认发送」等而未对歧义关键字做出选择，**不得**调用发送脚本，**必须**再次展示歧义列表并提示用户先指定具体人选（用户为序号或工号，群组为序号或群组名），待用户明确指定后再继续。

#### 展示格式

**逐个关键字展示，每个关键字一个表格**；群组多选时表格列为：序号、群组名（N）、部门（T），无工号；用户多选时为序号、姓名、工号、部门：

```
搜索结果显示，以下关键字匹配到多位用户/群组，需要您确认：

---

关键字「**王伟**」（收件人）匹配到多位用户，请确认要发送给哪一位：

| 序号 | 姓名 | 工号 | 部门 |
| ---- | ---- | ---- | ---- |
| 1    | 王伟 | 0668000589 | 办公自动化产品团队 |
| 2    | 王伟 | 10182695   | 网络优化部 |
| ...  | ...  | ...        | ... |

---

关键字「**雪飞**」（抄送人）匹配到多位用户，请确认要抄送给哪一位：

| 序号 | 姓名 | 工号 | 部门 |
| ---- | ---- | ---- | ---- |
| 1    | 彭雪飞 | 0668000393 | 办公自动化产品团队 |
| 2    | 韩雪飞 | 0668000223 | 开发三团队 |
| ...  | ...    | ...        | ... |

---

关键字「**项目组**」（收件人）匹配到多个群组，请确认要发送给哪一个：

| 序号 | 群组名 | 部门/描述 |
| ---- | ------ | --------- |
| 1    | $项目组A | 某某部门 |
| 2    | $项目组B | 某某团队 |
| ...  | ...    | ...       |

---

请回复各关键字对应的序号或工号来指定，例如「**王伟选第 1 个，雪飞选第 1 个**」或「**项目组选第 1 个**」。
```

#### 展示规则

- **表格中的姓名、工号、部门、群组名等必须全部来自 search-users 返回的对应字段（N、UNO、T、E 等），不得臆断、猜测或编造。**
- 每个歧义关键字**单独一个表格**，用分隔线 `---` 隔开。
- 表格标题中标注该关键字属于**收件人**还是**抄送人**，帮助用户理解上下文。
- 若某个关键字匹配用户/群组超过 10 个，只展示前 10 个，并在该表格下方提示「共匹配到 N 位用户/群组，仅展示前 10 位。用户建议用工号精确指定，群组用群组名（N）指定。」
- 已唯一匹配的关键字**无需展示**，仅告知用户（如「翁胜贵已唯一匹配」「项目组已唯一匹配，无需确认。」）；所述姓名/群组名**须为返回数据中的 N**，不得自编。
- **保存用户查询参数（title、body、to、cc、at）及所有歧义关键字的匹配列表到对话上下文**，等用户确认后直接使用。

#### 用户确认的解析规则

- 用户可能一次性回复所有选择，如「**王伟选第 1 个，雪飞选第 1 个，志扬选第 3 个**」。
- 也可能用工号指定（用户），如「**王伟用 0668000589，雪飞用 0668000393**」；群组用序号或群组名（N），如「**项目组选第 1 个**」。
- 从用户回复中**逐一解析**每个关键字的选择，使用**选中的工号（用户）或群组名 N（群组）**替换原关键字；群组解析只用 N，不使用 UNO。
- 若用户只确认了部分关键字，**再次询问**未确认的关键字。
- 所有歧义关键字都确认完毕后，**必须将「已解析的 to/cc」写入对话上下文**：to/cc 及群组字段只保存**邮箱 E**（用户或群组项中的 `E`），**不保存姓名、群组名、工号等关键字**。调用发送时**仅从该上下文组装 `--to`/`--cc`/`--bcc`**，禁止再次用关键字调用 search-users 或把姓名/群组名传给 send。

### 情况 B：`no_match_keys`（或群组时的 `no_match_cc_keys` / `no_match_bcc_keys`）不为空

**不发送邮件**，提示用户：

```
未找到与「**{关键字}**」匹配的用户/群组，请确认姓名、工号或群组名是否正确。
```

**注意**：邮箱地址（如 `user@example.com`）不会出现在 `no_match_keys` 中，会直接作为外部收件人。

### 情况 C：无同名、无多群组、无未匹配

每个关键字恰好匹配 1 个用户或 1 个群组，或为邮箱地址。直接进入后续流程（如 send 的步骤 3 展示邮件信息并等待用户确认）。

---

## search-users 失败（stderr）

参数校验失败或接口错误时，stderr 可能为 `{"status": false, "error": "具体错误信息"}`（例如 to/cc/bcc 同时为空等），退出码非 0。须将 **error** 原文展示给用户。
