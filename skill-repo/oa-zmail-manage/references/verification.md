# 验证方式（需求清单）

本页为 oa-zmail-manage 技能的触发条件、输入/输出规范、工作流与验证清单，便于稳定、复用与回归自检。

## 触发条件

- 用户输入匹配以下几类之一时加载本技能：
  - **收件箱**：含「未读」「紧急」「标星」「主送」等关键词的列表/查看场景
  - **发件箱**：含「发件箱」「已发送」「我发出的邮件」等列表场景
  - **总结**：含「总结」「汇总」「归纳」「提炼」等
  - **草稿箱**：含「草稿箱」「草稿」「看草稿」「第 N 封设时间/取消/立即发/删除」等
  - **新建邮件**：含「给 xxx 发邮件」「发一封邮件给 xxx」（提到具体发送时间则为预约发送）等
  - **搜索**：含「搜索」「查找」等，且无总结/收件箱/发邮件意图
  - **查看**：含「查看第 N 条」「查看这封」「看一下邮件内容」等，且无总结/收件箱/发邮件意图
  - **回复**：含「回复」「回这封」「回邮件」等，且无总结/收件箱/发邮件意图

## 输入/输出规范

| 类型     | 说明 |
|----------|------|
| **输入** | 用户自然语言（含时间、收件人、关键词等）；收件人为「我」或相对时间（今天/明天/本周等）时须先通过脚本解析 |
| **输出** | 邮件列表（表格）、邮件正文（Markdown）、摘要文本、发送/回复状态（JSON 或提示文案）等，形式见各子技能 reference 的「输出格式」或「展示规范」。**发件人/收件人/抄送人展示**：优先姓名+工号，无时用邮箱地址；群组=只显示名字；**发邮件/回复前须先展示信息并等待用户确认**。 |

## 工作流要点

1. 解析用户意图 → 确定子技能（收件箱/发件箱/总结/草稿箱/新建邮件/搜索/查看/回复，各可独立触发）
2. 若涉及「我」或相对时间 → 先执行 `main.py my-info` 或 `main.py get-time`，再继续
3. 打开该子技能对应的 reference，按其中工作流程与脚本说明执行
4. 脚本调用统一使用 `python3 {baseDir}/scripts/main.py <子命令> ...`（仅此入口，无其他独立脚本）
5. 错误时按 reference 的「错误处理」与 [scripts_and_errors.md](scripts_and_errors.md) 展示错误信息

## 验证清单

- [ ] **意图识别**：用户表述能正确映射到收件箱/发件箱/总结/草稿箱/新建邮件/搜索/查看/回复之一（各可独立触发；含子技能交叉说明）
- [ ] **时间与「我」**：相对时间仅依据 `main.py get-time` 输出；收件人为「我」时仅使用 `main.py my-info` 返回的 user 代表「我」，不将「我」等关键字传给接口
- [ ] **子命令与参数**：调用的 `main.py` 子命令及参数与各 reference 中脚本说明一致
- [ ] **错误展示**：脚本失败或接口错误时，将脚本/接口返回的 error 原文展示给用户，不篡改或省略
- [ ] **输出形式**：列表、详情、摘要、发送结果等格式符合对应 reference 的「输出格式」或「展示规范」；发件人/收件人/抄送人按类型展示（人优先姓名+工号，无时用邮箱；群组=名字）；发邮件/回复前须先展示并获用户确认后再发送
