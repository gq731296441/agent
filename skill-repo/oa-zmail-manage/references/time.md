# 时间

与主技能 [SKILL.md](../SKILL.md) 配合使用。收件人为「我/自己」时见 **[me.md](me.md)**；工作流、意图交叉、错误与展示约定见 **[workflow.md](workflow.md)**。本文档包含：**强制规则**（`get-time`、参数格式、定时发送）、**调用示例**，以及**自然语言时间表达**的分类、解析规则与展示规范。

## 时间与参数格式约定（调用脚本时）

时间类参数若为日期时间，格式为 **YYYY-MM-DD HH:MM:SS**、**YYYY-MM-DD HH:MM** 或 **YYYY-MM-DD**（搜索/总结的 `--start-date`/`--end-date` 支持精确到秒；定时发送的 `--at` 精确到分钟）；仅「最近 N 天」时传 **`--days N`**。收件人/抄送人/密送人多值时用 **`,`** 分隔；草稿 ID 多个时用 **`,`** 分隔。

## 时间解析（相对时间必须来自脚本）

凡涉及「今天」「明天」「本周」「本月」等**相对时间**的解析，**必须以该技能 `main.py get-time` 的输出为唯一依据**，禁止使用对话、客户端或 IDE 提供的"当前日期"。

- **必须执行**：先运行 `python3 {baseDir}/scripts/main.py get-time`，仅用输出 JSON 中的 `date`、`datetime`、`year`、`month`、`day`、`hour` 等计算相对日期与钟点。
- **禁止**：不得使用对话中的"当前日期"、user_info / Today's date 等；若 `get-time` 执行失败（报错、无输出、超时），**不得**用其他来源猜测"今天"，**必须**由用户提供具体日期或天数（如 `--days 7` 或 `2026-02-28 14:00`），**禁止**自行修改脚本或猜测。
- **输出格式**：需要传给脚本的**发送时间**须为 **YYYY-MM-DD HH:MM**（用户提到具体发送时间时）；仅需"最近 N 天"时传 `--days N` 即可。
- **详细规则**：相对日/周/月表达、仅「N点」时的默认含义、展示规范等见下文「常见时间表达分类」起各节。

### 调用 get-time

```bash
python3 {baseDir}/scripts/main.py get-time
```

#### 入参

无（无位置参数与可选参数）。

#### 出参（stdout JSON）

**成功**：

| 字段 | 类型 | 说明 |
|------|------|------|
| date | string | 日期 YYYY-MM-DD |
| time | string | 时间 HH:MM:SS |
| datetime | string | 完整日期时间 |
| timezone | string | 时区（如 Asia/Shanghai） |
| year | number | 年 |
| month | number | 月 |
| day | number | 日 |
| hour | number | 时 |
| minute | number | 分 |
| second | number | 秒 |
| weekday | string | 星期（英文） |
| timestamp | number | Unix 时间戳 |

```json
{"date": "2026-03-14", "time": "10:30:00", "datetime": "2026-03-14 10:30:00", "timezone": "Asia/Shanghai", "year": 2026, "month": 3, "day": 14, "hour": 10, "minute": 30, "second": 0, "weekday": "Saturday", "timestamp": 1773643800}
```

**失败**：stderr：`{"error": "具体错误信息"}`，退出码非 0。

## 定时发送时间识别与周期提醒

- **主题/正文中的时间不是发送时间**：用户发送定时邮件时，**仅用户明确说出的「发送时间」**（如「明天 9 点发」「下周一下午发」）作为 create-draft 的 `--at` 参数。邮件**主题或正文**里出现的时间（如会议时间、截止日期、活动日期等）**不得**当作发送时间使用；若用户未单独说明发送时刻，按未识别出具体发送时间处理，**一律立即发送**。
- **周期/循环提醒本技能不支持**：如「每个月 3 号」「每周一提醒」「每年生日」等**循环、周期**的时间提醒，本技能**不支持**。应告知用户使用系统或产品提供的**定时任务**等功能实现，当前技能仅支持**单次**在指定时刻发送一封邮件。

## 示例（含 get-time；涉及「我」时配合 my-info）

以下示例中，收件人为「我」的步骤以 **me.md** 为准。

### 示例 1：给「我」在明天上午 9 点发一封邮件

- 用户输入：「明天上午 9 点给我发一封邮件，提醒提交周报」。
- 调用顺序示例：
  1. `get-time`：获取当前日期时间，用于解析「明天上午 9 点」为具体 `YYYY-MM-DD 09:00`。
  2. `my-info`：获取当前用户信息，用返回的 `user` 代表收件人「我」。
  3. 如需补全/确认更多收件人时再调用 `search-users`。
  4. 使用 `create-draft --to ... --title ... --body ... --at 解析出的发送时间` 调度发送。

### 示例 2：今天给张三发一封立即发送的邮件

- 用户输入：「今天给张三发一封邮件，内容是提醒他明天 3 点开会」。
- 调用顺序示例：
  1. `get-time`：解析「今天」，但正文里的「明天 3 点」仅作为正文内容，不作为发送时间。
  2. `search-users --to 张三`：解析收件人张三。
  3. 通过 `search-users` 返回结果构造 `--to`/`--cc`/`--bcc`。
  4. 使用 `send --to ... --title ... --body ...` 立即发送（不传 `--at`）。

### 示例 3：查看今天收件箱的未读邮件

- 用户输入：「查看我今天的未读邮件」。
- 调用顺序示例：
  1. `get-time`：获取当前日期时间，用于解析「今天」的开始与结束时间（例如 `YYYY-MM-DD 00:00:00` 到 `YYYY-MM-DD 23:59:59`）。
  2. `my-info`：获取当前用户信息，用于需要时标注「我」相关上下文（收件箱默认即为当前用户的收件箱，不把「我」当作搜索关键字）。
  3. 使用 `search-emails "" --mailbox-type inbox --start-date ... --end-date ... --categories unread` 搜索今天的收件箱未读邮件。
  4. 按 [search.md](search.md) 的展示规范输出结果列表；若用户继续说「查看第 N 封」，再调用 `view <邮件ID>`（单封 ID）展示具体邮件内容。

## 何时需要解析（发送 / 搜索 / 草稿）

- **用户提到具体发送时间**时（如「明天早上 9 点」「下周一下午 3 点」）：草稿设发送时间、新建邮件预约发送，须先解析为具体日期时间再传给 `main.py operate-draft` / `main.py create-draft`。
- 脚本只接受 **YYYY-MM-DD HH:MM** 或 Unix 时间戳，不接受自然语言，故必须先完成解析再调用。
- **「定时」「定时邮件」等词不算用户提到具体发送时间**；只有用户说出**可解析的具体时刻**（如明天9点、下午3点）才算；仅说「定时」而无具体时刻 → 按未识别出具体发送时间处理，一律立即发送，不询问。
- **若用户说出了可识别的时间表述但无法解析为具体时刻**（如「明天某个时候」、表述模糊、有歧义）：**应询问用户确认具体时间**，待用户补充后再解析。

## 常见时间表达分类

### 1. 当天时间表达
- **"上午"、"早晨"、"早上"**：指当天上午（00:00-11:59）
- **"下午"、"傍晚"、"晚上"**：指当天下午/晚上（12:00-23:59）
- **"中午"**：指当天中午（11:00-13:00）
- **"午夜"**：指当天午夜（00:00左右）
- **"凌晨"**：指当天凌晨（00:00-05:00）

### 2. 相对日表达
- **"今天"**：当前日期
- **"明天"**：当前日期 + 1天
- **"昨天"**：当前日期 - 1天
- **"后天"**：当前日期 + 2天
- **"前天"**：当前日期 - 2天
- **"大后天"**：当前日期 + 3天
- **"大前天"**：当前日期 - 3天

### 3. 相对周表达
- **"本周"**：当前周（周一至周日）
- **"下周"**：当前周 + 1周
- **"上周"**：当前周 - 1周
- **"周末"**：当前周的周六和周日
- **"周一"、"周二"..."周日"**：当前周的具体某一天，如果已经过去则指下周的对应日

### 4. 相对月表达
- **"本月"**：当前月
- **"下月"**：当前月 + 1个月
- **"上月"**：当前月 - 1个月
- **"月底"**：当前月的最后一天
- **"月初"**：当前月的第一天
- **"月中"**：当前月的15号左右
- **"这个月初/底"**：等同于「本月」的月初/月底
- **"上个月初/底"**：上个月的第一天/最后一天
- **"下个月初/底"**：下个月的第一天/最后一天
- **"几月初/底"**（如 3 月初、十月底）：指定月份（1～12）的第一天或最后一天；需区分农历/公历若上下文涉及农历

### 5. 相对年表达
- **"今年"**：当前年
- **"明年"**：当前年 + 1年
- **"去年"**：当前年 - 1年
- **"年初"**：当前年的开始
- **"年底"**：当前年的结束
- **"今年初/底"、"明年初/底"、"去年初/底"**：对应年份的 1 月 1 日左右 / 12 月 31 日左右
- **"xxx年初/底"**（如 2024 年初、明年年底）：指定年份的第一天/最后一天；若为相对年（今年/明年/去年）则先换算成具体年份再取初/底

### 6. 半年与季度表达
- **"上半年"**：当前年的 1 月 1 日～6 月 30 日（若当前已在下半年，可指“今年上半年”或按上下文指某年上半年）
- **"下半年"**：当前年的 7 月 1 日～12 月 31 日
- **"Q1"、"Q1季度"、"第一季度"**：1 月～3 月
- **"Q2"、"Q2季度"、"第二季度"**：4 月～6 月
- **"Q3"、"Q3季度"、"第三季度"**：7 月～9 月
- **"Q4"、"Q4季度"、"第四季度"**：10 月～12 月
- 可与年份组合，如「今年 Q2」「2024 年底」：先确定年份，再取对应季度或年底

### 7. 时间范围表达
- **"这周内"**：本周剩余时间内
- **"本月内"**：本月剩余时间内
- **"今年内"**：今年剩余时间内
- **"最近几天"**：未来3-5天内
- **"近期"**：未来1-2周内

### 8. 时刻询问表达
- **"几点"**：询问或指代某日的具体时刻，需结合上下文确定是今天/明天/某日
- **"今天几点"**：今天的具体时刻，若未给出则需用户补充或解释为「今天某一时刻」
- **"明天几点"、"后天几点"**：明天/后天的具体时刻，同样若未给出具体钟点可说明为「该日某一时刻」并建议用户补充
- **仅说「N点」**（如 3点、5点，未带上午/下午）：先判断当前是上午还是下午。**当前为上午**（00:00–11:59）时，指**当天下午 N 点**（即 12+N 点，如 3点 → 15:00）；**当前为下午/晚上**（12:00–23:59）时，指**次日凌晨 N 点**（如 3点 → 次日 03:00）

### 9. 时长表达（相对一段时间）
- **"几个小时"、"几分钟"、"几十分钟"**：从当前或某参考点起算的小时/分钟数（如「过 3 个小时」= 当前 + 3 小时）
- **"几个半小时"**：同上，以半小时为单位（如 2 个半小时 = 1 小时）
- **"几天"、"几周"、"几个月"**：从当前或指定日期起算的天/周/月数；如「3 天后」= 当前日期 + 3 天
- 解析时需区分「过去」（如 3 天前）与「未来」（如 3 天后），并结合「从何时起算」

## 解析规则

### 基本解析流程
1. **获取当前时间**：通过 `get-time` 获取准确的当前系统时间（见上文「时间解析」）。
2. **识别时间表达**：确定用户使用的时间表达属于哪个分类
3. **计算具体时间**：根据当前时间和表达式规则计算具体时间
4. **考虑边界情况**：处理时间表达可能存在的歧义

### 特殊处理规则

#### 当天时间表达的边界
- 如果当前时间是上午，用户说"下午"：指今天下午
- 如果当前时间是下午，用户说"上午"：通常指明天上午（除非上下文明确指今天上午）

#### 周表达的偏移
- 如果今天是周三，用户说"周一"：通常指已经过去的本周一，还是下周的周一？
  - 默认：如果已经过去，指下周的周一
  - 上下文提示：根据任务紧急程度判断

#### 仅说「N点」的默认含义（未带上午/下午）
- 先根据当前时刻判断是上午（00:00–11:59）还是下午/晚上（12:00–23:59）
- **当前是早上/上午**：用户说「3点」→ 指**今天下午 3 点**（15:00）
- **当前是下午/晚上**：用户说「3点」→ 指**明天凌晨 3 点**（次日 03:00）
- 其他「N点」同理：上午时段指当天下午 N 点，下午时段指次日凌晨 N 点（避免与已过去的当天下午 N 点混淆）

#### 节假日考虑
- 如果用户说"工作日"：排除周末和节假日
- 如果用户说"节假日"：指周末或法定节假日

## 解析示例

### 示例1：解析"下午开会"
```
当前时间：2025-02-24 14:30:00
解析步骤：
1. "下午" → 当天时间表达，指12:00-23:59
2. 当前时间14:30在下午范围内
3. 结果：今天（2025-02-24）下午，具体12:00-23:59
```

### 示例2：解析"明天上午提交报告"
```
当前时间：2025-02-24 16:45:00
解析步骤：
1. "明天" → 相对日表达，当前日期+1天 = 2025-02-25
2. "上午" → 当天时间表达，指00:00-11:59
3. 结果：明天（2025-02-25）上午，具体00:00-11:59
```

### 示例3：解析"下周一开会"
```
当前时间：2025-02-24（周一）
解析步骤：
1. "下周一" → 相对周表达
2. 今天是周一，"下周一"指下周的周一
3. 计算：当前日期 + 7天 = 2025-03-03
4. 结果：2025年3月3日（周一）
```

### 示例4：解析"本月月底"
```
当前时间：2025-02-15
解析步骤：
1. "本月" → 当前月（2025年2月）
2. "月底" → 月份的最后一天
3. 2025年2月有28天（非闰年）
4. 结果：2025-02-28
```

### 示例5：解析"3点"（仅说钟点、未带上午/下午）
```
当前时间：2026-02-25 11:23:00（上午）
解析步骤：
1. "3点" 未带上午/下午 → 按当前时段判断
2. 当前为上午（11:23 < 12:00）→ 指当天下午 3 点
3. 结果：今天（2026-02-25）下午 3 点，即 2026-02-25 15:00
```

```
当前时间：2026-02-25 18:00:00（下午）
解析步骤：
1. "3点" 未带上午/下午 → 按当前时段判断
2. 当前为下午（18:00 ≥ 12:00）→ 指次日凌晨 3 点
3. 结果：明天凌晨 3 点，即 2026-02-26 03:00
```

## 展示规范（输出须含「日」）

向用户说明日期时**必须包含「日」**，避免只写年月：
- **单日**：使用「X年X月X日」，如 2026年2月25日
- **整月**：使用「X年X月1日至X月X日」（最后一天按该月实际天数），如 2026年3月1日至3月31日
- **范围**：起止都带日，如 2026年2月28日至3月1日

不得只写「2026年3月」而不写具体日期（日）。

## 注意事项

### 1. 时区考虑
- 所有时间都基于脚本获取的系统时区
- 如果用户提到其他时区，需要进行时区转换

### 2. 文化差异
- 不同文化对时间表达可能有不同理解
- 中文中"早上"可能指5:00-9:00，而英文"morning"可能指到12:00

### 3. 上下文依赖
- 某些时间表达需要结合对话上下文
- 例如："下午"在"明天下午"和"今天下午"中意义不同

### 4. 模糊表达的澄清
- 如果时间表达过于模糊，应该请求用户澄清
- 例如："最近"可以指几天到几周，需要明确

## 实用技巧

### 1. 使用脚本验证
在给出最终时间解释前，运行本技能内脚本验证当前时间：
```bash
python3 {baseDir}/scripts/main.py get-time
```

### 2. 提供明确的时间范围
避免使用模糊描述，提供具体的日期时间范围：
- ❌ "下午晚些时候"
- ✅ "今天下午3点到5点之间"

### 3. 考虑用户意图
根据用户任务类型调整时间解释的精确度：
- 会议安排：需要精确到具体时间点
- 任务截止：需要明确日期
- 一般讨论：可以相对宽松
