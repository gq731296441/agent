# 草稿箱相关操作（参考）

本参考描述**查看草稿箱**、**草稿在指定时间发送**（用户提到具体发送时间时）、**取消草稿已设的发送时间**、**立即发送草稿**、**删除草稿箱邮件**、**新建草稿邮件**、**新建邮件预约发送**七类场景的详细步骤与数据格式。

**本流程必读**：执行草稿箱相关操作时，建议按顺序阅读：① **SKILL.md**（路径与入口）、**[time.md](time.md)**（相对时间、定时发送与自然语言表达；草稿设时间/取消/立即发/新建邮件预约发送均涉及相对时间，须先 `main.py get-time`）；② **本页**（draft_box.md）场景一～七。脚本失败、无草稿列表却说「第 N 封」、序号超范围、时间解析失败等**错误处理**见 [scripts_and_errors.md](scripts_and_errors.md)。

---

## 场景一：查看草稿箱

### 触发条件

用户输入中包含「草稿箱」「草稿」「草稿邮件」「草稿列表」等关键词。

### 步骤1：调用脚本获取草稿列表

在技能目录下执行：

```bash
python3 {baseDir}/scripts/main.py draft-list [--pno N] [--psize N]
```

### 步骤2：解析脚本返回的 JSON

脚本标准输出为 JSON，格式：

```json
{
  "count": 3,
  "list": [
    {
      "id": "邮件ID",
      "ssd": "2026-02-12 09:00:00",
      "title": "邮件标题",
      "mt": ["李浩0668000"],
      "date": "2026-02-10 14:30:00"
    }
  ]
}
```

字段说明：

- `id`：草稿邮件 ID（后续设具体发送时间时使用）
- `ssd`：预设发送时间经脚本格式化后的字符串（如 `YYYY-MM-DD HH:MM:SS`）；未设定或为空时表示未预约发送。底层可能为时间戳，stdout 中已为展示用字符串。
- `title`：邮件标题
- `mt`：收件人展示列表（经脚本 `format_mt_list` 格式化，常见为 `["姓名+工号", ...]` 等字符串列表，以实际返回为准）
- `date`：最后更新时间（脚本格式化为可读时间字符串）

失败时 stderr 为 `{"error": "具体错误信息"}` 且退出码非 0；部分异常场景也可能得到 `{"count": 0, "list": []}`，须结合退出码与 [scripts_and_errors.md](scripts_and_errors.md) 处理。

### 步骤3：保存上下文并展示列表

**关键**：将草稿列表（含每条的 `id`）**保存到对话上下文**中，后续用户说「第 N 封」时可直接通过序号查找对应 `id`。

展示格式（带序号、高亮标题和收件人）：

```
您的草稿箱共有 **{count}** 封邮件：

| 序号 | 标题 | 收件人 | 更新时间 | 发送时间 |
| ---- | ---- | ------ | -------- | -------- |
| 1    | **邮件标题1** | 李浩0668000 | 2026-02-10 14:30:00 | — |
| 2    | **邮件标题2** | 张三0668001 | 2026-02-09 10:00:00 | 2026-02-12 09:00:00 |
| ...  | ... | ... | ... | ... |

您可以说「**第 1 封明天早上 9 点发送**」来设置具体发送时间，说「**第 2 封取消定时**」来取消已设的发送时间，说「**第 1 封立即发送**」来立刻发出，或说「**第 2 封删除**」来删除草稿。
```

- 若 `ssd` 为空，发送时间列显示 `—`。
- 若 `count` 为 0，提示「草稿箱为空」。

## 场景二：草稿在指定时间发送

### 触发条件

用户输入中包含序号引用（如「第 1 封」「第 3 个」）+ **具体发送时间**（如「明天 9 点」「下午 3 点发」），且**对话上下文中已有草稿列表**。

### 参数

| 要素     | 是否必填 | 说明 |
| -------- | -------- | ---- |
| 序号     | 必填     | 用户指定的草稿序号（从 1 开始） |
| 发送时间 | 必填     | 用户指定的发送时刻，需从自然语言解析 |

### 步骤1：解析参数

1. 从用户输入中解析**序号**（如「第 2 封」→ 序号 2）。
2. 从对话上下文的草稿列表中，按序号取到对应的 `id`。**若上下文中无草稿列表，提示用户先查看草稿箱。**
3. **检查该草稿的 `ssd` 字段**：若 `ssd` 不为空（即已设具体发送时间），**不调用脚本**，直接提示用户：

   > ⚠️ 草稿「**{标题}**」已设置发送时间（**{ssd}**），请先说「**第 N 封取消定时**」取消当前设置后，再重新设置。

   提示后**终止流程**，不继续执行后续步骤。

4. 从用户输入中解析**发送时间**，**必须转为 `YYYY-MM-DD HH:MM` 格式后再传给脚本**。脚本只接受该格式或 Unix 时间戳，不接受自然语言。

#### 时间解析规则

按 **[time.md](time.md)**（何时需要解析、输出格式、表达分类与示例）执行：先运行 `python3 {baseDir}/scripts/main.py get-time` 获取当前系统时间，仅用脚本输出计算相对日期与钟点；脚本失败时须由用户提供具体时间。常用示例见下表（假设当前为 2026-02-11 周三 15:00）：

须根据 **get-time** 输出与 [time.md](time.md) 规则，将用户的自然语言时间转为具体日期时间。以下为常用示例（假设当前为 2026-02-11（周三）15:00）：

| 用户输入 | 转换结果 | 说明 |
| -------- | -------- | ---- |
| 今天下午 6 点 | 2026-02-11 18:00 | 当天 + 下午6点=18:00 |
| 今天晚上 8 点 | 2026-02-11 20:00 | 当天 + 晚上8点=20:00 |
| 明天早上 9 点 | 2026-02-12 09:00 | 明天 + 早上9点=09:00 |
| 明天下午 3 点 | 2026-02-12 15:00 | 明天 + 下午3点=15:00 |
| 后天上午 10 点 | 2026-02-13 10:00 | 后天 + 上午10点=10:00 |
| 下午 3 点 | 2026-02-11 15:00 | 未指定日期默认今天 |
| 下周一上午 9 点 | 2026-02-16 09:00 | 下周一 = 当前周三往后推到下周一 |
| 周五下午 2 点 | 2026-02-13 14:00 | 本周五 |
| 2026-02-12 09:00 | 2026-02-12 09:00 | 已是标准格式，直接使用 |

更多表达（如「下周一」「周五下午」「3点」未带上午/下午等）按 [time.md](time.md)「常见时间表达分类」解析。

**时间词对照**：早上/上午 = 6:00~11:59，中午 = 12:00，下午 = 13:00~17:59，晚上 = 18:00~23:59。

### 步骤2：调用脚本设置草稿发送时间

在技能目录下执行：

```bash
python3 {baseDir}/scripts/main.py operate-draft --draft "<草稿ID>" --at "YYYY-MM-DD HH:MM"
```

- `--draft`：从上下文草稿列表中按序号取到的 `id`
- `--at`：解析后的发送时间

### 步骤3：解析返回并输出

脚本成功时标准输出：

```json
{"status": true, "mid": "邮件ID", "send_at": 1739336400}
```

失败时标准错误输出含 `"error"` 键。

输出格式：

```
✅ 草稿「**{标题}**」已设置发送时间，将于 **{YYYY-MM-DD HH:MM}** 发出。

如需进一步操作，请登录 [zMail Web 邮箱](https://zmail.zte.com.cn) 处理。
```

- 标题从上下文草稿列表的对应项中获取。

## 场景五：删除草稿箱邮件

> 说明：收件箱、草稿箱、发件箱、自定义文件夹中的“删除”或者“移动到已删除（回收站）”须用 **`delete-mails`**，**禁止**用 `move-emails` 代替删除；该删除操作**不是永久删除**，可以通过恢复操作恢复。

### 触发条件

用户输入中包含序号引用（如「第 1 封」「第 3 个」）+ 删除意图（如「删除」「删掉」「不要了」），且**对话上下文中已有草稿列表**。也支持一次删除多封（如「删除第 1、2 封」）。

### 参数

| 要素     | 是否必填 | 说明 |
| -------- | -------- | ---- |
| 序号     | 必填     | 用户指定的草稿序号（从 1 开始），可多个（逗号或顿号分隔） |

### 步骤1：解析参数

1. 从用户输入中解析**序号**（如「第 2 封」→ 序号 2；「第 1、3 封」→ 序号 1、3）。
2. 从对话上下文的草稿列表中，按序号取到对应的 `id` 列表。**若上下文中无草稿列表，提示用户先查看草稿箱。**
3. 若序号超出范围或无效，提示用户并终止。

### 步骤2：调用脚本将草稿移动到已删除（回收站）

在技能目录下执行：

```bash
python3 {baseDir}/scripts/main.py delete-mails --email-id "<草稿ID1>,<草稿ID2>,..."
```

- `--email-id`：从上下文草稿列表中按序号取到的 `id`，多个用英文逗号分隔。

### 步骤3：解析返回并输出

脚本成功时标准输出示例：

```json
{"status": true}
```

失败时标准错误输出含 `"error"` 键。

输出格式：

```
✅ 已将草稿「**{标题1}**」、「**{标题2}**」等共 **{N}** 封移动到已删除（回收站）。

如需进一步操作，请登录 [zMail Web 邮箱](https://zmail.zte.com.cn) 处理。
```

- 标题从上下文草稿列表的对应项中获取；单封时可只写一封标题。

## 场景六：新建草稿邮件

### 触发条件

**必须明确识别到用户希望保存为草稿而非发送**时才触发。触发关键词示例：「保存到草稿」「存草稿」「写个草稿」「先存着不发」「帮我草拟一封邮件保存到草稿箱」。

> **注意**：若用户说「发邮件给 xxx」「给 xxx 发邮件」等**未表达保存草稿意图**的表述，应走**发送**流程（[send.md](send.md)），**不触发本场景**。

### 参数

| 要素 | 是否必填 | 说明 |
|------|----------|------|
| 收件人 | 选填 | 收件人（个人或群组），须通过 [search-users](search-users.md) 确认；不填则保存无收件人草稿 |
| 标题 | 选填 | 邮件标题，不填则为空 |
| 正文 | 选填 | 邮件内容，不填则为空 |
| 抄送人 | 选填 | 抄送人（个人或群组） |
| 密送人 | 选填 | 密送人（个人或群组），与 send 一致 |
| 附件 | 选填 | 本地文件路径，多个用逗号分隔；路径须符合 Windows 与 Linux。脚本会校验文件存在性、总大小（≤30MB）、可读权限。路径为文件夹时须先列出该目录下所有文件供用户确认后再传入。 |
| 图片插入正文 | 条件可选 | **CLI 入参** `--is-inline`：与 [send.md](send.md) 参数表「图片插入正文」行同语义。**仅当未传 `--draft`**（新建草稿）时可带；**传 `--draft`（编辑已有草稿）时**不得使用非默认的 `--is-inline`。 |

### `--is-inline` 路由（把图片插入正文；场景六专用，供模型判定）

| 用户意图 | 须调用的子命令 |
|----------|----------------|
| 仅保存草稿、无「图片插入正文」要求 | `save-draft`（本场景） |
| 保存草稿 + 把图片插入正文 + **新建**（无 `--draft`） | `save-draft`（本场景）+ `--attachments` + `--is-inline "1"` |
| 把图片插入正文 + **编辑已有草稿**（有 `--draft`） | `save-draft` **不支持**；改 `send` / `create-draft` 或先保存为普通附件 |
| 把图片插入正文 + 立即发 | `send`，见 [send.md](send.md) |
| 把图片插入正文 + 预约发 | `create-draft`，见**场景七** |

### 步骤1：解析参数并确认收件人

与发送邮件流程一致：

1. 从用户输入中解析收件人、抄送人、密送人、标题、正文、附件。
2. **若用户要把图片插入正文（或说插图）且将编辑已有草稿**（会传 `--draft`）：**不得**对 `save-draft` 使用 `--is-inline`；须改走 `send` / 场景七，或先按普通附件保存。
3. 收件人、抄送人、密送人须通过 [search-users](search-users.md) 确认（存在多名匹配时由用户指定），与发送邮件的确认规则相同。
4. **收件人、抄送人、密送人均可选**；不填则保存无收件人草稿。

### 步骤2：展示草稿预览并等待确认

**在调用脚本之前**，向用户展示草稿预览信息：

```
**草稿预览**

**标题**：{标题或"（无标题）"}
**收件人**：张三（0668000001）；李四（0668000002）（无则显示「无」）
**抄送人**：王五（0668000003）（无则不显示该行）
**密送人**：{密送人}（无则不显示该行）
**附件**：{附件路径列表}（无附件时省略此行）
**正文**：
{正文内容或"（空）"}

请回复「**确认保存**」将邮件保存到草稿箱，或说明需要修改的内容。
```

- 若用户要求修改某一项：更新后重新展示，再次等待确认。
- 若用户回复「**确认保存**」「**保存**」「**存草稿**」等明确保存意图：进入下一步。

### 步骤3：调用脚本保存草稿

在技能目录下执行：

有收件人/抄送/密送时：

```bash
python3 {baseDir}/scripts/main.py save-draft --title "<标题>" --body "<正文>" [--to ...] [--cc ...] [--bcc ...]
```

无收件人时省略 `--to`/`--cc`/`--bcc`：

```bash
python3 {baseDir}/scripts/main.py save-draft --title "标题" --body "正文"
```

有附件时追加 `--attachments`（多个路径逗号分隔）：

```bash
python3 {baseDir}/scripts/main.py save-draft --title "标题" --body "正文" --to "a@example.com" --attachments "/path/to/file1.txt,/path/to/file2.pdf"
```

新建草稿且需把图片插入正文时（**未传** `--draft`）：

```bash
python3 {baseDir}/scripts/main.py save-draft --title "标题" --body "正文" --attachments "/path/to/a.png,/path/to/b.pdf" --is-inline "1"
```

编辑已有草稿时传 `--draft`：

```bash
python3 {baseDir}/scripts/main.py save-draft --draft "<草稿ID>" --title "标题" --body "正文"
```

编辑已有草稿且调整附件时：`--attachments` 为逗号分隔的**新增**本地文件路径；`--attachments-del` 为逗号分隔的**待删除**附件 ID（来自草稿详情或 view 中的附件 `id`）。

```bash
python3 {baseDir}/scripts/main.py save-draft --draft "<草稿ID>" --attachments "/path/to/new_file.pdf" --attachments-del "原附件ID1,原附件ID2"
```

仅删除附件不传新文件时，可省略 `--attachments` 或传空，只传 `--attachments-del`。仅新增不传删除时，只传 `--attachments`。

- **`--is-inline`**：仅**未传 `--draft`** 时可用；与 `send` / `create-draft` 同语义；**传 `--draft` 时**不得使用非默认的 `--is-inline`。见上文「`--is-inline` 路由」表。

- `--to` / `--cc` / `--bcc`：可选。逗号分隔邮箱，与 `send` / `create-draft` 一致。无收件人时可不传。
- `--title`：邮件标题（可为空）。
- `--body`：邮件正文（可为空）。
- `--attachments`：可选。逗号分隔的本地文件路径，表示**添加**的附件（无 `--draft` 时为新建草稿附带上传；有 `--draft` 时为在原有 ATS 上追加新文件）。
- `--is-inline`：可选，`"0"` \| `"1"`，默认 `"0"`；**仅**未传 `--draft` 时有效；与 `--draft` 联用时**勿**传 `"1"`。
- `--attachments-del`：可选。**仅与 `--draft` 联用**，逗号分隔的附件 ID，表示从原草稿 ATS 中**删除**的附件。
- 编辑草稿时若不想修改附件：不传 `--attachments` 与 `--attachments-del`（或两者均为空）。
- `save-draft` 会先获取原草稿详情与原 ATS，再按 `--attachments-del` 删除、按 `--attachments` 上传并追加，最后保存更新后的草稿。
- 待删除 ID 中不存在于原草稿附件列表的项会记录日志并跳过；上传路径中文件不存在时会直接报错。
- `--draft`：可选。传入后按该草稿 ID 更新保存，不再新建 ID；未传的标题、正文、收件人、附件会按规则从原草稿回填。

#### 编辑草稿与定时发送（重要）

- 使用 **`save-draft` 且传入 `--draft`** 时，保存结果为**普通草稿**（**不含**定时发送时间），**不会在保存时保留或延续**原草稿的「定时发送」。
- 若当前草稿原本是**定时邮件**，用户仅要求「保存修改」而未说明要继续定时 → 保存后即变为**普通草稿**，**不会**继续按原时间发送。
- 若用户**明确要求**修改后仍定时发送（保持**原预约时间**或指定**新的具体时间**）：应在 **`save-draft` 成功之后**（或用户一句话里同时表达保存与定时意图时，按顺序先 save 再 operate）再调用 **`operate-draft --draft "<草稿ID>" --at "<时间>"`**；`--at` 须为可解析的具体时刻（与 `create-draft` / 场景二一致）。
- **注意**：列表里若该草稿带 `ssd`/预约时间，编辑保存后若用户说「还是原来那个时间发」「改完明天 9 点再发」等，应在保存成功后补充一次 `operate-draft`。

### 步骤4：解析返回并输出

脚本成功时标准输出：

```json
{"status": true, "mid": "邮件ID"}
```

失败时标准错误输出含 `"error"` 键。

输出格式：

```
✅ 邮件「**{标题}**」已保存到草稿箱。

您可以稍后在草稿箱中查看并发送，或登录 [zMail Web 邮箱](https://zmail.zte.com.cn) 进一步编辑。
```

- 若标题为空，显示「（无标题）」。

## 场景七：新建邮件预约发送

### 触发条件

用户说「给 xxx 发邮件」「发一封邮件给 xxx」等，且**明确提到具体发送时间**（如「明天 9 点」「下午 3 点发」「下周一下午发」）。**「定时」「定时邮件」等词不算具体发送时间**；只有用户说出**可解析的具体时刻**（如明天 9 点、下午 3 点）才算；仅说「定时」而无具体时刻 → 按未识别出具体发送时间处理，走 [send.md](send.md) 立即发送。

> **注意**：本场景与**场景六（新建草稿）**不同——本场景是**新建邮件并预约在指定时间发送**；场景六是**保存到草稿箱**。若用户未表达保存草稿意图，应走发送流程（立即发送见 send.md，预约发送见本场景）。

### 参数

| 要素     | 是否必填 | 说明 |
| -------- | -------- | ---- |
| 收件人   | 选填     | 与 [send.md](send.md) 一致；收件人、抄送人、密送人**不能同时为空**，至少填一项；须通过 [search-users](search-users.md) 确认 |
| 邮件标题 | 必填     | 预约发送时**必须填写标题**，脚本会校验 |
| 发送时间 | 必填     | 用户指定的发送时刻，须转为 `YYYY-MM-DD HH:MM` 后传给脚本 |
| 抄送人   | 可选     | 与 send.md 一致 |
| 正文     | 可选     | 与 send.md 一致 |
| 附件     | 可选     | 本地文件路径，多个用逗号分隔；路径须符合 Windows 与 Linux，如 `/home/work/1.txt`。脚本会校验文件存在性、总大小（≤30MB）、可读权限。路径为文件夹时须先列出该目录下所有文件供用户确认后再传入。 |
| 图片插入正文 | 可选 | **与 `send` 同参**：`--is-inline "0"` \| `"1"`，默认 `"0"`；与 `--attachments` 联用，`"1"` 时仅**图片**插入正文。语义单一事实来源：[send.md](send.md) 参数表「图片插入正文」行。 |

### 步骤1：解析参数并确认收件人

与 [send.md](send.md) 步骤 1～2 一致：解析收件人、抄送人、密送人、标题、正文、附件；**若用户要把图片插入正文**，从用户输入解析 `is_inline`（`"1"` / 否则 `"0"`），供步骤 4 拼 `create-draft` 时传入 `--is-inline`。**若收件人、抄送人、密送人全空**：提示「收件人、抄送人、密送人不能同时为空，请至少填写一项」，流程结束。有则须通过 [search-users](search-users.md) 确认（存在多名匹配时由用户指定）。

### 步骤2：解析发送时间

从用户输入中解析**发送时间**，**必须转为 `YYYY-MM-DD HH:MM` 格式后再传给脚本**。脚本只接受该格式或 Unix 时间戳，不接受自然语言。

#### 时间解析规则

与**场景二**一致，按 **[time.md](time.md)** 执行：先运行 `main.py get-time` 获取当前系统时间，仅用脚本输出计算相对日期与钟点。常用示例见场景二「时间解析规则」表格；更多表达见 [time.md](time.md)。

**时间词对照**：早上/上午 = 6:00~11:59，中午 = 12:00，下午 = 13:00~17:59，晚上 = 18:00~23:59。

若用户表述模糊无法解析（如「明天某个时候」），应询问用户确认具体时间，待用户补充后再解析。

### 步骤3：展示邮件信息（含发送时间）并等待用户确认

与 [send.md](send.md) 步骤 3 一致，**展示时须包含发送时间**：

```
请确认以下邮件信息，确认无误后回复「**确认发送**」即可在该时间发出；如需修改，请直接说明要改的内容。

---

**当前邮件信息：**

- **标题**：{title}
- **收件人**：{to}
- **抄送**：{cc}（无抄送时显示「无」）
- **发送时间**：{YYYY-MM-DD HH:MM}
- **附件**：{attachments}（无附件时省略此行）
- **正文**：
{body}

---

请回复「**确认发送**」在该时间发送，或说明需要修改的内容。
```

- 展示规则、用户回复处理、修改时的处理规则与 send.md 步骤 3 一致。附件路径为文件夹时须先列出该目录下所有文件供用户确认后再传入。
- **保存当前邮件参数到对话上下文**：title、to、cc、body、attachments、**at**（解析后的发送时间）、**is_inline**（`"0"` \| `"1"`，供步骤 4 拼 `--is-inline`）。

### 步骤4：调用脚本预约发送（仅用户确认后执行）

**前置条件**：必须已完成步骤 3 并向用户展示邮件信息，且用户已明确回复「确认发送」「发送」「发吧」等发送意图**或**用户意图可识别为「直接发送」。

在技能目录下执行：

```bash
python3 {baseDir}/scripts/main.py create-draft --title "<标题>" [--to "<邮箱1,邮箱2>"] [--cc ...] [--bcc ...] --body "<正文>" --at "YYYY-MM-DD HH:MM"
```

有附件时追加 `--attachments`（多个路径逗号分隔）：

```bash
python3 {baseDir}/scripts/main.py create-draft --title "标题" --to "a@example.com" --body "正文" --at "YYYY-MM-DD HH:MM" --attachments "/path/to/file1.txt,/path/to/file2.pdf"
```

**`--is-inline` 拼命令规则（与 [send.md](send.md) 步骤 4 同表）**：`attachments` 非空且 `is_inline=="1"` 时追加 `--is-inline "1"`；否则不传或 `--is-inline "0"`。

```bash
python3 {baseDir}/scripts/main.py create-draft --title "标题" --to "a@example.com" --body "正文" --at "YYYY-MM-DD HH:MM" --attachments "/path/to/a.png,/path/to/b.pdf" --is-inline "1"
```

- `--title`：**必填**，预约发送时邮件必须填写标题。
- `--to` / `--cc` / `--bcc`：与 send 一致，须为步骤 1 通过 [search-users](search-users.md) 确认后的邮箱。
- `--body`：正文，可选。
- `--at`：**必填**，预定发送时间，格式 `YYYY-MM-DD HH:MM`。
- `--attachments`：附件路径，多个用逗号分隔，可选。
- `--is-inline`：见 [send.md](send.md) 步骤 4「`--is-inline`（是否把图片插入正文）」表；**禁止**与 `save-draft --draft` 同用非默认 `--is-inline`。

### 步骤5：解析返回并输出

脚本成功时标准输出：

```json
{"status": true, "mid": "邮件ID", "send_at": 1739336400}
```

失败时标准错误输出含 `"error"` 键。

输出格式（成功）：

```
✅ 邮件已设置在该时间发送！

- **标题**：{title}
- **收件人**：{to}
- **抄送**：{cc}（无抄送时省略此行）
- **发送时间**：{YYYY-MM-DD HH:MM}

如需进一步操作，请登录 [zMail Web 邮箱](https://zmail.zte.com.cn) 处理。
```
