# 邮件总结

当用户需要**总结、汇总、归纳或提炼**邮件内容时使用此技能。**默认总结收件箱**；当用户明确要求总结**发件箱**（我发出的邮件）时，传 `--mailbox-type outbox`。参数与 `search-emails` 子命令一致，支持 `--mailbox-type`、`--sender`、`--recipients`、`--cc`、`--content`、`--attachment-name`、`--mail-attribute`、`--folder`、`--categories`、`--days`、`--start-date`、`--end-date` 及位置参数 `keyword`。**总结必须严格基于脚本返回的 `content` 字段，不得随意捏造。**

**发件箱展示特别约定**：发件箱中的邮件均为当前用户本人发出，**展示发件箱总结时不展示任何发件人相关信息**（不展示工号、名字、邮件地址等）。内部/外部段仅写「您共发出 **X** 封邮件」及分类列表；分类列表子项格式为「• 主题或简述（N封）」，**不得**出现「（发件人：XXX，N封）」。

**无邮件类型不输出**：内部、外部、公邮三类中，**若某类没有邮件**（`user_count` 为 0 或 `mail_count` 为 0），则**整段不输出**，不得输出该类型标题及任何一句汇总语（例如不得输出「外部邮件：您共收到 0 位发件人的 0 封邮件」或「外部邮件：您共收到 0 位发件人的 0 封未读邮件。」等）。仅当某类有邮件时才输出该段（类型标题 + 汇总行 + 分类列表）。

---

**⚠️ 发件箱输出硬性约束（所有模型必须严格遵守）**

- **发件箱 = 我发出的邮件，发件人即当前用户本人。** 总结发件箱时**禁止**在分类列表子项中出现任何发件人信息（包括但不限于：姓名、工号、邮箱、「发件人：XXX」「谢飞武」「多封」等）。
- **正确格式**：子项**仅**写「• 主题或简述（N封）」；**错误示例**：❌「• 主题（谢飞武，多封）」、❌「• 主题（发件人：XXX，N封）」。
- 汇总行写「您共发出 **{mail_count}** 封邮件」（发件箱不写「X 位发件人」）。换用任何模型执行本技能时，均须按此约定输出，不得沿用收件箱的「（发件人：XXX，N封）」格式。

---

**总则**：本技能中凡出现「**必须**」「**MUST**」「**必填**」「**不可省略**」的条目，均为**硬性约束**，输出时缺一不可；执行步骤4前须按「输出前自检清单」逐项核对后再回复用户。  
**【硬性要求】输出总结结果时，须严格按照本文件「输出格式模板」与示例中的标题、段落与列表结构进行排版，不得自定义或变更整体结构（包括额外增加自定义小节、表头或标题样式）。**

## 触发条件

**必须满足**：用户输入中显式包含与「概括邮件内容」相关的意图词，例如：

- **总结**、**汇总**、**归纳**、**提炼**、概括、梳理
- 帮我总结下、总结一下、汇总一下、归纳下、提炼要点、概括一下 等

**可选**：参数与 `search-emails` 一致（收件箱/发件箱、发件人、收件人、抄送人、日期范围、关键字、正文、附件名、邮件属性、文件夹、分类等）。未指定时使用脚本默认（收件箱、发件人为空则按所有发件人汇总，日期使用脚本默认天数，关键字为空）。时间范围以脚本返回的 **`start_date`**、**`end_date`**、**`default_days`** 为准。

| 要素     | 是否必填 | 说明 |
| -------- | -------- | ---- |
| 总结意图 | 必填     | 总结、汇总、归纳、提炼、概括、梳理、帮我总结下、总结一下、汇总一下、归纳下、提炼要点 等 |
| 箱体类型 | 可选     | **默认收件箱**。当用户说「发件箱」「我发出的」「发出的邮件」「总结我发的邮件」等时传 `--mailbox-type outbox`；未识别到则传默认（inbox） |
| 分类     | 可选     | **优先解析**。逗号分隔：`unread,starred,urgent,to_me`；需要仅总结未读邮件时传 `--categories unread` |
| 发件人   | 可选     | 发件人姓名，如李四、李浩、张三 |
| 日期     | 可选     | **开始/结束日期**（如「今年2月10日到2月18日」）优先于 **最近 N 天**；未指定起止日期时可用显式 N 天或语境推断；实际范围以返回的 start_date、end_date、default_days 为准 |
| 关键字   | 可选     | 搜索关键字；脚本会同时按标题与正文匹配并去重 |

## 触发场景

以下情况**会触发**（含总结/汇总/归纳/提炼等意图词）：

- "帮我**总结**下最近发的邮件"
- "**总结**一下**李浩**发的带有**合规**的邮件"
- "帮我**总结**下**李四**最近发的邮件"
- "**汇总****张三**最近一周的邮件"
- "**归纳**下**王五**发的关于合同的邮件"
- "**提炼**一下**李四**发的邮件要点"
- "**总结****李四**最近发的邮件带有**合规**的邮件"
- "**总结**今年2月10日到2月18日的邮件"、"**汇总**2月10日到18日的邮件"（传入 --start-date 与 --end-date）；"**总结**从2月10日以来的邮件"（仅传 --start-date，脚本以当前日为结束）
- "**总结**春节期间的邮件"、"**汇总**假期期间的邮件"（从语境推断时间范围，无需用户明确说「最近 N 天」）
- "**总结**休假期间的邮件"、"**汇总**休假期的邮件"（先查技能列表是否有可查休假期的技能，有则用其取日期；没有则询问用户）
- "**总结**未读邮件"、"**汇总**未读邮件"、"**归纳**一下最近的未读邮件"（传入 `--categories unread`，可与日期/发件人/关键字组合）
- "**总结**发件箱的邮件"、"**汇总**我发出的邮件"、"**归纳**一下最近发件箱"（传入 `--mailbox-type outbox`，可与日期组合）

以下情况**不会触发**（无总结/汇总/归纳/提炼等意图）：

- "李四最近发的邮件"（无概括意图）
- "搜索合规的邮件"（无概括意图）

## 查询参数解析

### 箱体类型解析（可选，默认收件箱）

- **默认**：不传 `--mailbox-type` 或传 `--mailbox-type inbox`，表示总结**收件箱**（收到的邮件）。
- **发件箱**：当用户明确表示要总结「发件箱」「我发出的」「发出的邮件」「我发的邮件」等时，传 **`--mailbox-type outbox`**。
- **其他箱体**：支持 `deleted`（已删除）、`spam`（垃圾邮件）、`folder`（指定文件夹，需配合 `--folder`），与 search-emails 一致。
- **识别示例**：总结发件箱、汇总我发出的邮件、归纳一下最近发出的、总结我最近发的邮件 → `--mailbox-type outbox`。

### 分类解析（可选，优先解析）

- 当用户输入中**显式包含与「未读」相关的表述**时，传 `--categories unread`；未识别到时不传，脚本默认统计全部邮件（含已读、未读）。
- **支持的分类**（逗号分隔）：`unread`（未读）、`starred`（标星）、`urgent`（紧急）、`to_me`（主送我），可组合使用。
- **识别模式**：未读、未读邮件、只总结未读、仅未读、汇总未读、归纳未读邮件、总结最近的未读 等 → `--categories unread`。
- 可与发件人、日期、关键字任意组合，例如：「总结李四最近一周的未读邮件」→ 发件人=李四，--days 7，--categories unread。

### 发件人解析（可选）

- 从用户输入中识别具体人名或工号组合，作为 `--sender` 参数；未指定发件人时不传 `--sender`。
- 示例：李四、李浩、李浩06680001352、张三。
- 当用户按表格序号指定时（如「总结表格中第 2 个」「总结表格中第 2 个和第 4 个」）：用最近一次展示的用户列表（脚本返回的 `users`）中第 N、第 M 项对应的 `id` 作为 `--sender`，再次调用脚本并总结（支持单个或多个序号）。

### 开始/结束日期解析（可选，优先级高于 days）

**规则**：若能识别到**开始日期**（可选结束日期），则使用 `--start-date`，有结束日期时再传 `--end-date`；否则使用下面的天数解析，传 `--days N`。

- **同时有开始和结束**：传入 `--start-date YYYY-MM-DD --end-date YYYY-MM-DD`，不传 `--days`。
- **只有开始、无结束**：仅传入 `--start-date YYYY-MM-DD`，不传 `--end-date`；**结束日期按当前日期**（「当前」须以 [time.md](time.md) 的 `get-time` 为准）。
- **无法识别开始日期**：改用天数解析，传 `--days N`。

- **示例**：用户说「总结今年2月10日到2月18日的邮件」→ `--start-date 2026-02-10 --end-date 2026-02-18`。用户说「总结从2月10日以来的邮件」→ 仅传 `--start-date 2026-02-10`。
- **表述形式**：2月10日到2月18日、从2月10日到2月18日、2月10日以来、从2月10日起 等；需根据当前年份补全为 YYYY-MM-DD。
- **按需使用时间解析**：解析「本周」「本月」「下周」「2月10日」等自然语言日期时，按 **[time.md](time.md)** 确定具体日期或范围，转为 `--start-date`/`--end-date` 或用于推断 `--days N`。

### 天数解析（可选）

当**未**使用开始/结束日期时，将自然语言或**用户语境**转为 `--days N`。**支持四类解析**：  
1）**显式表述**：用户直接说「最近 N 天」「本周」「本月」等，按下表映射。  
2）**语境推断**：用户未明确说天数，但从上下文可推断时间范围（如「上周的邮件」「本周」「本月」）时，可根据 get-time 与语境推断出合理的 N。**注意：涉及春节、国庆、五一等节日假期时不能推断**，必须走第 3）条使用搜索。
3）**涉及假期必须使用搜索（不能推断假期）**：**春节、国庆、五一等节日假期的具体起止日期不得自行推断**，必须通过外部搜索获取。若涉及**春节、国庆、五一等节日假期**，**须先查看当前技能列表中是否有外部搜索/联网搜索类技能**：**若有**，则**必须调用**该技能查询（如「2026年春节放假时间」「今年国庆假期 日期」）确定起止日期，并传 `--start-date` 与 `--end-date`，**不得传 `--days`**；**若没有**，则**必须提醒用户**安装外部搜索技能或直接告知起止日期，并**等待用户重新输入后再继续**，不得擅自传 `--days` 或使用脚本默认。**若调用后搜索失败或无结果**，则**提示用户安装外部搜索技能**（如：「无法通过搜索获取放假日期，请先安装外部搜索/联网搜索类技能后再试，或直接告诉我起止日期。」），并**等待用户重新输入后再继续**，不得传 `--days` 或默认。
4）**休假期**：当用户提到「休假期」「休假期间的邮件」等时，**须先查询当前技能列表**，看是否存在能查询休假期/请假日期等的技能：**若有**，则调用该技能获取休假起止日期，并**必须**传 `--start-date` 与 `--end-date`，**不得传 `--days`**；**若没有**，则**询问用户**（如：「当前没有可查询休假期的技能，请告知休假起止日期，以便为您总结邮件。」），**等待用户重新输入后再继续**，待用户补充后传 `--start-date` 与 `--end-date`。

**约定（需联网时）**：凡需通过互联网查询才能确定具体日期时（节日假期、活动时段等），**先查当前技能列表是否存在外部搜索/联网搜索技能**；有则调用，没有则提示用户安装该类技能并说明否则无法确定日期，或请用户直接提供起止日期/“最近 N 天”。

**约定（提示用户后须等待）**：凡因无法获取日期/条件而**提醒或询问用户**（如请安装外部搜索技能、请告知起止日期、请告知休假日期等）时，**须等待用户重新输入后再继续**，不得擅自传 `--days`、使用脚本默认或继续执行；仅当用户补充信息或重新发起请求后，再根据用户输入继续处理。

**约定（假期必须使用搜索，不能推断假期）**：**节日假期（春节、国庆、五一等）的具体放假起止日期不能推断**，不得根据自身知识或语境自行推断假期日期。凡涉及**假期**（春节、国庆、五一等节日假期、假期期间）的时间范围，**必须使用外部搜索/联网搜索技能查询**（如「2026年春节放假时间」「今年国庆放假日期」等）获得起止日，**不得擅自传 `--days` 或使用脚本默认**。有外部搜索技能则必须调用该技能查询；若当前没有该技能，则提醒用户安装联网/搜索类技能，并说明否则无法确定假期具体日期，或请用户直接告知起止日期，**等待用户重新输入后再继续**。**若调用外部搜索后搜索失败或无结果**，则**提示用户安装外部搜索技能**（或直接告知起止日期），**等待用户重新输入后再继续**，不得传 `--days` 或默认。获得起止日后**必须**传 `--start-date` 与 `--end-date`，**不得使用 `--days`**。

**时间范围与展示**：脚本返回 **`start_date`**、**`end_date`**、**`default_days`**。**标题必须区分收件箱与发件箱**：根据本次调用为 **收件箱**（`--mailbox-type inbox` 或未传）还是 **发件箱**（`--mailbox-type outbox`），在标题中明确写出「**收件箱**」或「**发件箱**」。若使用**开始/结束日期**，用「从{start_date}至{end_date}期间**收件箱/发件箱**邮件的总结」；若使用 **days**，用「最近 N 天 (start_date 至 end_date) 的**收件箱/发件箱**邮件的总结」；**仅当传入的 N 大于返回的 default_days 时**，须在标题中增加说明：「你选择的时间超过允许的 default_days 天，现在使用 default_days 天来总结」，否则不增加该提示。

### 关键字解析（可选）

- 从「带有 XXX」「包含 XXX」「关于 XXX」等中提取关键字，作为脚本的**第一个位置参数** `keyword`。**脚本会同时按邮件标题与正文搜索该关键字**（先按标题搜一次、再按正文搜一次，结果按邮件 ID 去重），因此会命中标题或正文任一包含关键字的邮件。

## 工作流程

**约定**：**只调用脚本一次**。返回中已包含 **`internal`**、**`external`**、**`public`**（各自含 `user_count`、`mail_count`、`content`），**总结必须严格基于 `internal.content`、`external.content` 与 `public.content` 做归纳，不得随意捏造**；输出时**先标题，再按内部、外部、公邮和系统邮件三段分别总结（若某类无邮件则不展示该类）**，每段先写多少人发多少封，再写分类列表。搜索结果超过 100 条时仅总结前 100 条。

### 步骤1：解析用户查询

从用户输入中提取：

```yaml
query_params:
  mailbox_type: "inbox"  # inbox/outbox/deleted/spam/folder，默认 inbox；用户说发件箱/我发出的 等时为 outbox
  keyword: ""            # 关键字，可选
  days: null             # 最近 N 天，可选；与 start_date/end_date 同时有时以日期为准
  start_date: ""         # 开始日期 YYYY-MM-DD 或 YYYY-MM-DD HH:MM:SS，可选；仅识别到开始日期时也可只传此项，脚本将结束日期设为当前日期
  end_date: ""           # 结束日期 YYYY-MM-DD 或 YYYY-MM-DD HH:MM:SS，可选；未识别到时不传，脚本用当前日期作为结束
  sender: ""             # 发件人，可选
  recipients: ""         # 收件人，可选
  cc: ""                 # 抄送人，可选
  content: ""            # 正文内容，可选
  attachment_name: ""    # 附件名称，可选
  mail_attribute: ""     # 邮件属性：attachment/external，可选
  folder: ""             # 文件夹名称（mailbox_type 为 folder 时），可选
  categories: ""         # 逗号分隔：unread,starred,urgent,to_me，可选
```

**天数 (days) 与起止日期的确定**：**假期（春节、国庆、五一等）不能推断**，凡涉及假期，**必须使用外部搜索（或可查休假期的技能）查询**得到起止日，再传 `--start-date`、`--end-date`，**不得使用 `days` 或脚本默认**。非假期的其他语境若无法推断 N，可查外部搜索后传 `--days N`；若仍无法确定则不传，使用脚本默认。

### 步骤2：调用脚本一次

在技能目录下执行（以项目内 `scripts` 所在目录为工作目录）：

**方式一：按搜索条件总结**（参数与 `search-emails` 一致）：

```bash
python3 {baseDir}/scripts/main.py summary [keyword] [--mailbox-type inbox|outbox|deleted|spam|folder] [--days N] [--start-date "YYYY-MM-DD"|"YYYY-MM-DD HH:MM:SS"] [--end-date "YYYY-MM-DD"|"YYYY-MM-DD HH:MM:SS"] [--sender NAME] [--recipients NAME] [--cc NAME] [--content TEXT] [--attachment-name NAME] [--mail-attribute attachment|external] [--folder NAME] [--categories unread,starred,urgent,to_me]
```

**方式二：按邮件 ID 直接总结**（传入 `--ids` 时忽略其他搜索参数）：

```bash
python3 {baseDir}/scripts/main.py summary --ids ID1,ID2,ID3
```

- **--ids**（可选）：邮件 ID 列表，逗号分隔。**传入时优先级最高**，直接按 ID 获取邮件内容并总结，忽略所有其他搜索参数（keyword、--mailbox-type、--days 等）。适用于用户已通过搜索/查看获得邮件 ID 后，指定特定邮件进行总结的场景。
- **--mailbox-type**（可选）：**不传或 `inbox`** 为收件箱总结；**`outbox`** 为发件箱总结；也支持 `deleted`、`spam`、`folder`。
- `keyword`（可选）：位置参数，搜索关键字。
- `--start-date` / `--end-date`（可选）：当用户说出起止日期时传入，格式 YYYY-MM-DD 或 YYYY-MM-DD HH:MM:SS（仅传日期时起始默认 00:00:00、结束默认 23:59:59）；与 `--days` 同时存在时以开始/结束日期为准。
- `--days`（可选）：当未使用开始/结束日期且用户指定了「最近 N 天」等时传入。
- `--sender`（可选）：发件人姓名或标识。
- `--recipients`（可选）：收件人。
- `--cc`（可选）：抄送人。
- `--content`（可选）：正文内容关键字。
- `--attachment-name`（可选）：附件名称。
- `--mail-attribute`（可选）：`attachment`（有附件）或 `external`（外部邮件）。
- `--folder`（可选）：文件夹名称（`--mailbox-type folder` 时使用）。
- `--categories`（可选）：逗号分隔，如 `unread,starred,urgent,to_me`；需要仅总结未读邮件时传 `--categories unread`。

脚本**标准输出**为 JSON；若退出码非 0 或输出含 `"error"` 键，视为失败。

### 步骤3：根据返回处理

返回格式为：`{"start_date", "end_date", "default_days", "internal": {"user_count", "mail_count", "content"}, "external": {...}, "public": {"user_count", "mail_count", "content"}}`（**发件箱时无 `public`**，仅含 `internal`、`external`）。搜索结果超过 100 条时仅总结前 100 条。

- **内部邮件内容**在 **`internal.content`**，**外部邮件内容**在 **`external.content`**，**公邮和系统邮件内容**在 **`public.content`**（**仅收件箱有 public**；仅含标题列表，发件人仅有名称无工号；格式为「用户标识 + 在查询范围内的邮件内容： + 【标题】…」）。  
- **当返回的邮件总数或发件人总数较多时**（例如邮件总数 ≥ 50 或发件人总数 ≥ 10）：在输出标题之后、各段总结正文之前，**必须先输出一句耐心等待提醒**，大意：本次邮件量和发件人较多，总结内容较长，生成需要一定时间，请您耐心等待。  
- **先输出标题**（若有上述较多情形则标题后紧跟耐心等待提醒），再**按内部、外部、公邮和系统邮件三段分别总结**（**发件箱无公邮段**）：**仅当某类有邮件时**（该段 `user_count` > 0 且 `mail_count` > 0）才展示该类。**收件箱**每段先写「您共收到 **{user_count}** 位发件人的 **{mail_count}** 封邮件」，再基于该段 `content` 做分类列表，子项含「（发件人：XXX，N封）」；**发件箱**每段先写「您共发出 **{mail_count}** 封邮件」，再基于该段 `content` 做分类列表，子项**仅**写「• 主题或简述（N封）」，**不展示发件人/工号/名字/邮件地址**。内部、外部、公邮中无邮件的分类**不展示**。

若返回 `{"error": "异常信息"}`，按「错误处理」处理。
### 步骤4：向用户输出的汇总（仅当返回含 internal、external、public 的 content 时执行）

**约定：凡标注「必须」「MUST」「必填」「不可省略」的项，一律视为硬性约束；输出时缺任一项即视为未按技能执行，不得以“可选”“可省略”处理。**

**输出前自检清单**（执行本步骤时须逐项满足，再向用户输出）：
- [ ] 邮件数/发件人较多时：若邮件总数 ≥ 50 或发件人总数 ≥ 10，已在标题之后、总结正文之前输出耐心等待提醒（大意：总结内容较长，请耐心等待）。
- [ ] 标题行：**已区分收件箱/发件箱**（收件箱写「收件箱」、发件箱写「发件箱」）；已按 days/起止日期规则书写；N > default_days 时已加「你选择的时间超过允许的…」说明。
- [ ] **无邮件分类不展示**：内部、外部、公邮三类中，若某类 `user_count` 为 0 或 `mail_count` 为 0，则**整段不输出**，**不得**输出该类型标题及汇总语（例如**禁止**输出「内部邮件：您共收到 0 位发件人的 0 封邮件」「外部邮件：您共收到 0 位发件人的 0 封未读邮件。」等任何 0 人/0 封的段落）。
- [ ] 内部邮件（仅当有邮件时）：已写「**内部邮件**：您共收到 **{user_count}** 位发件人的 **{mail_count}** 封邮件，主要包括以下几类：」+ 分类列表（**发件箱**时改为「您共发出 **{mail_count}** 封邮件」，分类列表子项不包含发件人/工号/名字/邮箱）
- [ ] 内部分类列表：每类为「**数字. 类别名 (N封, 占X%):**」+「• 主题（发件人：XXX，N封）」；**发件箱**时子项仅为「• 主题或简述（N封）」，**禁止出现发件人姓名/工号/邮箱**（发件人即本人，换模型也须遵守）。当本次总结的邮件总数 `internal.mail_count + external.mail_count + public.mail_count ≤ 3` 且某一分类下仅有 1 封邮件时，**必须**结合对应段落的 `content`，对这封邮件用 **2～3 句完整中文**说明清楚「这封邮件讲什么」「是否有需要跟进/注意的事项」，不得只给出简单类别名或一行标题。
- [ ] 外部邮件（仅当有邮件时）：已写「**外部邮件**：您共收到 **{user_count}** 位发件人的 **{mail_count}** 封邮件，主要包括以下几类：」+ 分类列表（**发件箱**时改为「您共发出 **{mail_count}** 封邮件」，分类列表子项不包含发件人/工号/名字/邮箱）
- [ ] 外部分类列表：格式同内部（**发件箱**时子项仅为「• 主题或简述（N封）」）
- [ ] 公邮和系统邮件（仅当有邮件时，**仅收件箱有本段**）：已写「**公邮和系统邮件**：您共收到 **{user_count}** 位发件人的 **{mail_count}** 封邮件，主要包括以下几类：」+ 分类列表
- [ ] 公邮和系统邮件分类列表：格式同内部/外部（基于 **public.content**，仅含标题）；**发件人仅展示名称、无工号**，子项格式为「• 主题或简述（发件人：名称，N封）」。（**发件箱无 public，不输出本段。**）
- [ ] **重点事项提醒**（**必须输出**）：已输出「🔑 重点事项提醒」段落；若无事项则写「目前没有重点事项」。若含「即将召开的会议」，已确认**仅包含会议开始时间晚于当前日期时间的会议**，未包含任何已过期会议（输出前已逐条核对时间）。

**本步骤为面向用户的总结输出**。**输出顺序**：**先标题**；若邮件总数或发件人总数较多（如邮件总数 ≥ 50 或发件人总数 ≥ 10），**紧接着输出一句耐心等待提醒**（如：「本次邮件量和发件人较多，总结内容较长，生成需要一定时间，请您耐心等待。」）；**再按内部、外部、公邮和系统邮件依次输出**：**仅当该类有邮件时**（`user_count` > 0 且 `mail_count` > 0）才输出该段（多少人发多少封 + 分类列表），**无邮件的分类不展示**；然后**必须输出重点事项提醒**，最后可选总结后提醒。

**强制要求**：**所有总结内容必须严格基于返回的 `internal.content`、`external.content` 与 `public.content`**（标题、分类、主题、重点事项等均须来自邮件内容），**禁止凭想象或常识捏造、编造任何未在 content 中出现的内容**。若某段 content 中无某类信息，则不得输出该类信息。**分类与主题须结合每封邮件的标题与正文内容一起归纳**（公邮和系统邮件仅有标题，按标题归纳；发件人仅展示名称、无工号）；不得仅依据邮件标题进行归类或命名。

**禁止输出的内容**（必须严格遵守）：
- **不得**输出「主要发件人及邮件类型」作为标题或独立段落。
- **不得**以发件人为维度逐人展开（如「1. 谌磊… - N封邮件」「主要内容」「邮件类型」等）。
- **不得**输出「邮件分类分析」「关键发现」「建议」等独立小节或 emoji 小标题（如 🔍、🔧、📋、🔔、🎯、💡）。
- **不得**在某一类型无邮件时输出该类型段落（例如**禁止**输出「外部邮件：您共收到 0 位发件人的 0 封邮件」「外部邮件：您共收到 0 位发件人的 0 封未读邮件。」等；无邮件则整段省略，不输出该类型标题及任何一句话）。
- **仅允许**输出：标题行；内部邮件段（汇总数据行 + 分类列表）；外部邮件段（汇总数据行 + 分类列表）；**公邮和系统邮件段**（汇总数据行 + 分类列表，发件人仅写名称、无工号）；**重点事项提醒（必须输出）**；可选的总结后提醒。**若某类（内部/外部/公邮）无邮件，则不展示该类**。**收件箱**发件人信息**只**出现在分类列表每条子项的括号内：内部/外部格式为「（发件人：XXX，N封）」；公邮和系统邮件**仅写发件人名称、无工号**，格式为「（发件人：名称，N封）」；**发件箱**不展示发件人相关信息（无工号、名字、邮件地址），分类列表子项格式仅为「• 主题或简述（N封）」。

1. **标题行**（只输出一次）：**必须根据本次是收件箱还是发件箱在标题中明确写出「收件箱」或「发件箱」**。若本次调用使用的是 **开始/结束日期**（传了 `--start-date`/`--end-date`），用 **「从{start_date}至{end_date}期间【收件箱/发件箱】邮件的总结」**（收件箱时写「收件箱」，发件箱时写「发件箱」）；若使用的是 **days** 参数（传了 `--days N`），用 **「最近 N 天 ({start_date} 至 {end_date}) 的【收件箱/发件箱】邮件的总结」**（同样按收件箱/发件箱二选一）。**仅当 N 大于返回的 default_days 时**，须在标题中增加说明：「你选择的时间超过允许的 {default_days} 天，现在使用 {default_days} 天来总结」，否则不增加该提示。

2. **内部邮件**（仅当有邮件时输出一段）：  
   - **汇总数据行 + 引导句**：**收件箱**写「**内部邮件**：您共收到 **{internal.user_count}** 位发件人的 **{internal.mail_count}** 封邮件，主要包括以下几类：」；**发件箱**写「**内部邮件**：您共发出 **{internal.mail_count}** 封邮件，主要包括以下几类：」（**发件箱不展示发件人/工号/名字/邮箱**）。  
   - **分类列表**（建议 3～5 类）：必须按主题/内容归纳，不得按发件人分类。每类格式：**数字. 类别名 (N封, 占X%):**，其下用「•」列出：**收件箱**为**• 主题或简述（发件人：发件人姓名，N封）**；**发件箱**为**• 主题或简述（N封）**，不包含发件人相关信息。类别名与主题须来自 **`internal.content`** 的邮件标题与正文归纳；百分比 = 该类邮件数 / internal.mail_count × 100%。  
   - **若 internal 无邮件**（user_count 为 0 或 mail_count 为 0）：**不展示**本段。

3. **外部邮件**（仅当有邮件时输出一段）：  
   - **汇总数据行 + 引导句**：**收件箱**写「**外部邮件**：您共收到 **{external.user_count}** 位发件人的 **{external.mail_count}** 封邮件，主要包括以下几类：」；**发件箱**写「**外部邮件**：您共发出 **{external.mail_count}** 封邮件，主要包括以下几类：」（**发件箱不展示发件人相关信息**）。  
   - **分类列表**（建议 3～5 类）：规则同内部，须来自 **`external.content`**；**发件箱**子项仅为「• 主题或简述（N封）」；百分比 = 该类邮件数 / external.mail_count × 100%。  
   - **若 external 无邮件**：**不展示**本段。

4. **公邮和系统邮件**（仅当有邮件时输出一段，**仅收件箱有本段**；发件箱无 public，不输出）：  
   - **汇总数据行 + 引导句**：**公邮和系统邮件**：您共收到 **{public.user_count}** 位发件人的 **{public.mail_count}** 封邮件，主要包括以下几类：  
   - **分类列表**（建议 3～5 类）：规则同内部/外部，须来自 **`public.content`**（仅含标题，按标题归纳）；**发件人仅展示名称、无工号**，子项格式为「• 主题或简述（发件人：名称，N封）」；百分比 = 该类邮件数 / public.mail_count × 100%。  
   - **若 public 无邮件**：**不展示**本段。

5. **重点事项提醒**（**必须输出**，紧接在公邮和系统邮件分类列表之后）：  
   - 标题固定为：**🔑 重点事项提醒**  
   - 内容从 **`internal.content`、`external.content` 与 `public.content`** 中提炼需跟进的事项，例如：截止日期类、需反馈/提交类、**即将召开的会议**。  
   - **【硬性约束】会议时间**：**「即将召开的会议」中仅可列出会议开始时间晚于执行总结时的当前日期时间的会议**。凡会议开始时间早于或等于当前日期时间的，一律视为已过期，**不得**出现在重点事项中（既不得列入「即将召开的会议」列表，也不得用“以下会议已过期”“当前无即将召开的会议”等文字说明或列举）。**输出前必须逐条核对邮件中的会议开始时间**：仅保留“开始时间 > 当前日期时间”的会议；若所有会议均已过期，则重点事项中**不得出现**「即将召开的会议」小标题及任何会议名单，会议相关一句都不要写。

### 输出格式模板

**仅输出**步骤4的汇总：**先标题**，再**有邮件时才输出**内部邮件、外部邮件、公邮和系统邮件各段（每段：多少人发多少封 + 引导句 + 分类列表），**若某类无邮件则跳过不展示**；**发件箱无公邮段**，仅输出内部、外部。**发件箱**的汇总行写「您共发出 X 封邮件」，分类子项**不展示发件人/工号/名字/邮箱**，格式为「• 主题或简述（N封）」。然后**必须输出重点事项提醒**（若无则写「目前没有重点事项」），最后可选总结后提醒。**所有内容必须基于 `internal.content`、`external.content` 与 `public.content`**（发件箱无 public），不得随意捏造。**禁止**输出「主要发件人及邮件类型」、以发件人为维度的逐人介绍、「邮件分类分析」「关键发现」「建议」等独立小节；**收件箱**发件人信息仅出现在分类列表每条子项的「（发件人：XXX，N封）」中；**发件箱**不出现发件人相关信息。

- **内部/外部/公邮**：**仅当该段有邮件时**（user_count > 0 且 mail_count > 0）才输出该段；**某类无邮件时整段不输出**，不得出现「XX邮件：您共收到 0 位发件人的 0 封邮件」或「0 封未读邮件」等表述。**收件箱**先写「**内部邮件**」/「**外部邮件**」/「**公邮和系统邮件**」：您共收到 **{user_count}** 位发件人的 **{mail_count}** 封邮件，主要包括以下几类：，再基于对应 content 输出分类列表（子项含「（发件人：XXX，N封）」）；**发件箱**先写「您共发出 **{mail_count}** 封邮件」，分类列表子项仅为「• 主题或简述（N封）」，不展示发件人/工号/名字/邮箱。百分比分母分别为各段 mail_count；**公邮段发件人仅写名称、无工号**。**无邮件的分类不展示**。

- **重点事项提醒**（**必须输出**）：标题为「🔑 重点事项提醒」，内容从 **internal.content、external.content 与 public.content** 提炼（截止日期、需反馈/提交、即将召开的会议等）。**【硬性】「即将召开的会议」仅可列出会议开始时间晚于当前日期时间的会议**；已过期的会议既不要列举，也不要写“已过期”“无即将召开的会议”等说明——没有未来会议时，重点事项中完全不出现会议相关表述。输出前须逐条核对会议开始时间，只保留未召开的会议。**若邮件中出现「紧急」「重要」「需回复」等标识或表述，须在重点事项提醒中体现**（简要列出相关邮件或事项）。若未识别到任何重点事项，则输出：目前没有重点事项。

## 脚本说明

入口：**`main.py summary`**（统一入口 `{baseDir}/scripts/main.py`）。

### 用法

**只调用脚本一次** 支持两种模式：1）按搜索条件总结；2）传 `--ids` 按邮件 ID 直接总结（优先级最高，忽略其他搜索参数）。脚本先搜索（或直接按 ID），再拉取邮件正文并返回 `content`（搜索结果超过 100 条时仅总结前 100 条）。**发件箱返回无 `public`**，仅含 `internal`、`external`。

```bash
# 方式一：按搜索条件总结
python3 {baseDir}/scripts/main.py summary [keyword] [--mailbox-type inbox|outbox|deleted|spam|folder] [--days N] [--start-date "YYYY-MM-DD"|"YYYY-MM-DD HH:MM:SS"] [--end-date "YYYY-MM-DD"|"YYYY-MM-DD HH:MM:SS"] [--sender NAME] [--recipients NAME] [--cc NAME] [--content TEXT] [--attachment-name NAME] [--mail-attribute attachment|external] [--folder NAME] [--categories unread,starred,urgent,to_me]

# 方式二：按邮件 ID 直接总结（忽略其他搜索参数）
python3 {baseDir}/scripts/main.py summary --ids ID1,ID2,ID3
```

- **--ids**（可选）：邮件 ID 列表，逗号分隔。**传入时优先级最高**，直接按 ID 获取邮件内容并总结，忽略所有其他搜索参数。适用于已有邮件 ID 的场景。
- **--mailbox-type**（可选）：**不传或 `inbox`** 为收件箱总结；**`outbox`** 为发件箱总结；也支持 `deleted`、`spam`、`folder`。
- **keyword**（可选）：位置参数，搜索关键字。
- **--days N**（可选）：最近 N 天；不传则使用脚本默认。**与 --start-date/--end-date 同时传入时，以开始/结束日期为准**。
- **--start-date** / **--end-date**（可选）：开始、结束日期，格式 YYYY-MM-DD 或 YYYY-MM-DD HH:MM:SS（仅传日期时起始默认 00:00:00、结束默认 23:59:59）；**传入 start-date 即优先于 --days**。若只识别到开始日期（如「从2月10日以来的邮件」），仅传 `--start-date 2026-02-10`，脚本将结束日期设为当前日期。
- **--sender NAME**（可选）：发件人姓名或标识。
- **--recipients NAME**（可选）：收件人。
- **--cc NAME**（可选）：抄送人。
- **--content TEXT**（可选）：正文内容关键字。
- **--attachment-name NAME**（可选）：附件名称。
- **--mail-attribute**（可选）：`attachment`（有附件）或 `external`（外部邮件）。
- **--folder NAME**（可选）：文件夹名称（`--mailbox-type folder` 时使用）。
- **--categories**（可选）：逗号分隔，如 `unread,starred,urgent,to_me`；需要仅总结未读邮件时传 `--categories unread`。

### 出参（stdout JSON）

- **按搜索条件总结**返回：`{"start_date", "end_date", "default_days", "internal": {"user_count", "mail_count", "content"}, "external": {...}, "public": {"user_count", "mail_count", "content"}}`（**发件箱无 `public`**）。搜索结果超过 100 条时仅总结前 100 条。
- **按 ID 总结**（`--ids`）返回：`{"internal": {"user_count", "mail_count", "content"}, "external": {...}, "public": {...}}`，不含 `start_date`/`end_date`/`default_days`。
- **内部/外部邮件正文**在 **`internal.content`**、**`external.content`**，**公邮和系统邮件内容**在 **`public.content`**（**仅收件箱有 public**；仅含标题列表，发件人仅有名称无工号）。**先输出标题，再按内部、外部、公邮和系统邮件三段分别总结**（发件箱无公邮段）：每段先写多少人发多少封（使用该段 `user_count`、`mail_count`），再基于该段 `content` 做分类列表。

**按搜索条件总结**（含日期范围元数据时）示例：

```json
{
  "start_date": "2024-01-01",
  "end_date": "2024-01-15",
  "default_days": 14,
  "internal": {"user_count": 2, "mail_count": 5, "content": "按用户分组的邮件摘要..."},
  "external": {"user_count": 1, "mail_count": 2, "content": "..."},
  "public": {"user_count": 0, "mail_count": 0, "content": ""}
}
```

**按 `--ids` 直接总结**（无 `start_date` / `end_date` / `default_days`）示例：

```json
{
  "internal": {"user_count": 2, "mail_count": 5, "content": "..."},
  "external": {"user_count": 1, "mail_count": 2, "content": "..."},
  "public": {"user_count": 0, "mail_count": 0, "content": ""}
}
```

**失败**：stderr 如 `{"error": "异常信息"}`，退出码非 0；解析时以存在 `"error"` 键或非 0 退出为准。

## 错误处理

| 场景           | 处理方式 |
| -------------- | -------- |
| 脚本返回 error | 展示 `error` 中的提示，建议检查发件人、网络或重试 |
| 无邮件结果     | 提示未找到该发件人在指定条件下的邮件，建议放宽条件或确认发件人 |
| 认证/登录异常  | 提示需要重新登录或联系管理员 |
| **外部搜索失败**（如涉及假期需查放假日期时调用搜索失败、无结果或异常） | **提示用户安装外部搜索技能**（如：「无法通过搜索获取日期，请先安装外部搜索/联网搜索类技能后再试，或直接告诉我起止日期。」），**等待用户重新输入后再继续**，不得擅自传 `--days` 或使用脚本默认。 |
