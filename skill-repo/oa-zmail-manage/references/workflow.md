# 工作流：意图路由、错误与展示

加载 [SKILL.md](../SKILL.md) 选定 reference 后，本页与对应 reference 一并遵循。不确定 CLI 参数时执行 `python3 {baseDir}/scripts/main.py <子命令> --help`；子命令分组见 [cli_subcommands.md](cli_subcommands.md)。

## 基础规则（按需打开子文档）

| 主题 | 文档 |
|------|------|
| **「我」**（my-info、不得把「我」当搜索关键字等） | [me.md](me.md) |
| **时间**（参数格式、get-time、定时发送与周期、三条调用示例） | [time.md](time.md) |

**删除语义统一规则（强约束）**：收件箱、草稿箱、发件箱、自定义文件夹中的“删除”或者“移动到已删除（回收站）”须用 **`delete-mails`**，**禁止**用 `move-emails` 代替删除；该删除操作**不是永久删除**，可以通过恢复操作恢复。仅当用户明确说“撤回”且场景为发件箱时，才执行 `rollback-sent`。
**历史/归档邮件删除限制（强约束）**：历史邮件/归档邮件**不能删除**；当用户尝试删除时，必须明确告知「历史邮件/归档邮件不能删除」。

## 执行步骤

1. **意图**：从用户话里判定「发件箱 / 总结 / 发送 / 搜索 / 查看 / 附件下载 / 附件转存 / 邮件标记 / 文件夹 / 回复 / 转发」之一；多义时取更具体的。收件箱未读/紧急/标星/主送 → **搜索**（`search-emails --categories`）。
2. **文档**：在 SKILL.md 表格里打开该意图对应的 **唯一** reference。**执行每个子命令前**必须先加载该子命令对应的参考文档（见 SKILL.md「技能分类与 reference」表及文内子命令说明），再按其步骤拼命令并执行；同一流程中多次调用不同子命令时，每次执行前均须加载对应文档。
3. **CLI**：
   - 入口：`python3 {baseDir}/scripts/main.py <子命令> [参数]`。缺参数名或不确定必填项 → 先跑 `python3 {baseDir}/scripts/main.py <子命令> --help`，再拼命令；不要向用户索要参数格式。
  - 子命令与场景：**发件箱** 列表/搜索 `search-emails --mailbox-type outbox`，仅在明确“撤回”时用 `rollback-sent`；**总结** `summary`；**发送链** `search-users` + `send` 或 `create-draft`；**草稿** `draft-list`、`save-draft`、`operate-draft`（新建定时草稿也用 `create-draft`）；**搜索** `search-emails`；**正文** `view`；**附件** `download-attach`、`transfer-attach`；**标记** `mark-email`；**文件夹** `folder-list`、`delete-mails`、`move-emails`、`recover-mails`；**回复** `reply`、`reply-brief`；**转发** `check-forward`、`forward`；**时间 / 我** `get-time`、`my-info`。
4. **时间与「我」**：相对时间 [time.md](time.md)；收件人「我」 [me.md](me.md)。
5. **发邮件展示与确认**：新建邮件（main.py send / create-draft）**必须先向用户展示当前邮件信息**（标题、收件人、抄送、正文；若用户提到具体发送时间则含该时间）。**若用户明确表示希望直接发送**（如「直接发」「不用确认」「发吧别问了」「别确认了直接发」等），可**省去确认步骤**，展示后直接调用 send / create-draft；否则须**等待用户明确回复「确认发送」「发送」「发吧」等**之后才能调用。**禁止**在未展示且用户未表达直接发送意图的情况下不经确认即发送。**无论收件人是否唯一匹配，展示环节不可省略**；仅当用户意图可识别为「直接发送」时，可跳过确认等待。
6. **发送时多名匹配**：收件人/抄送人存在多名匹配（同名用户或多群组）时，**禁止**自行选人或选组（同部门、同团队、取第一项等；**用户与群组一视同仁**）；**必须**由用户明确指定具体人员或群组（用户为序号或工号，群组为序号或群组名）后，再展示或调用发送脚本；详见 [send.md](send.md) 情况 A。**调用 send/create-draft 时 `--to`/`--cc`/`--bcc` 须为 search-users 确认后的邮箱**，**禁止在发送时再用关键字搜人或传姓名/群组名**。
7. **群组无权限（强硬要求）**：发送时若某群组没有权限（如返回「用户没有权限使用邮件组」），**不得自行改选其他群组**，直接向用户提示「xx 群组没有权限」或原文展示脚本返回的 error，由用户决定是否更换收件人。
8. **展示须严格依据 search-users 返回（强硬要求）**：展示用户/群组（姓名、工号、部门、群组名、邮箱等）时，**必须严格按照 search-users 返回的数据**展示，**禁止臆断、猜测、编造**任何未在返回中的内容。**发邮件与回复邮件展示时，优先使用姓名+工号**（如「谢飞武（0668001367）」），**没有姓名或工号时再使用邮件地址**。
9. **半年限制**：若返回 JSON 含 `beyond_half_year: true`，向用户说明：「半年前的邮件请使用历史邮件查询」。
10. **输出**：表格/Markdown/链接等按各 reference「输出格式」「展示规范」。
11. **默认值**：用户未说的参数若脚本用了默认值，在回复里写出本次实际使用的默认值（具体句式见各 reference）。

## 子技能交叉说明

- **「查邮件」「搜索邮件」「查找邮件」** 且无「总结」「未读/紧急/标星/主送」「发邮件」等词 → 使用 **搜索**。**默认范围即为收件箱**，与用户说「我的收件箱」等价。
- **「我的收件箱」「收件箱邮件」** 且**未**带未读/紧急/标星/主送 → 与「查找邮件」一致，使用 **搜索**（默认收件箱）。
- **「查看第 N 条」「看某标题邮件」「打开邮件」「预览附件」** 或直接给出邮件 ID → 使用 **查看**。附件预览属于查看能力，返回的 `preview_url` **仅作为 Markdown 链接展示给用户，禁止使用任何工具（WebFetch、Shell curl、浏览器等）去访问或读取该地址**。
- **「下载附件」「保存附件到本地」「导出附件」** 且指定邮件与保存路径 → 使用 **附件下载**（[attachment.md](attachment.md)）。
- **「标为已读 / 标为未读 / 加星 / 取消星标 / 收藏 / 去星」** 等**改邮件状态**（含「第 N 封」「这几封」「未读里关于 XX 的都标已读」）→ **邮件标记**（[mark.md](mark.md)，`mark-email`）。**仅**「列出 / 筛选」未读、紧急、标星、主送邮件，**不**改状态 → **搜索**（[search.md](search.md)，`search-emails --categories`）。
- **「把附件转存到云盘」「附件存到网盘」** → 使用 **transfer-attach**，`--email-id` 必填，`--attach-ids` 可选。
- **「文件夹列表」「查看文件夹」「我的文件夹」** → 使用 **文件夹**（[folder.md](folder.md)）。
- **「删除邮件」「移到已删除（回收站）」**（含收件箱/发件箱/文件夹内邮件）→ 使用 **`delete-mails --email-id`**（**禁止**用 `move-emails` 代替）。
- **删除目标为历史邮件/归档邮件** → 直接返回错误并明确告知「历史邮件/归档邮件不能删除」，不发起删除请求。
- **「移动邮件到收件箱/垃圾邮件/某文件夹」**（非删除）→ 使用 **move-emails**，`--mailbox-type` 为 `inbox` / `spam` / `folder`。**识别到目标是自定义文件夹时，`--mailbox-type` 传 `folder` 且 `--folder` 必填**；传了 `--folder` 时目标以文件夹解析为准。
- **当邮件已在“已删除/回收站”且用户再次要求删除** → 明确告知不支持“再次删除已删除邮件”，不执行撤回或其他替代动作。
- **「回复」「回邮件」「回复这封邮件」** 且给出回复内容 → 使用 **回复**。
- **「转发」「转给 xxx」「把这封邮件转发给 xxx」** → 使用 **转发**（[forward.md](forward.md)）。
- **明确说「总结」「汇总」「归纳」** → 使用 **总结**。
- **含「未读」「紧急」「标星」「主送」** 且为收件箱筛选场景 → 使用 **搜索**（[search.md](search.md)），`--mailbox-type inbox` 且 `--categories` 传对应分类。
- **含「发件箱」「已发送」「我发出的邮件」** 且为列表/搜索场景 → 使用 **搜索**（[search.md](search.md)），`search-emails --mailbox-type outbox`；明确说“撤回”才使用 **发件箱**（[outbox.md](outbox.md)）的 `rollback-sent`；说“删除”则走 **`delete-mails`**。
- **「草稿箱」「看草稿」「第 N 封设时间/取消/立即发/删除」「保存到草稿」「存草稿」「写个草稿」** → 使用 **草稿箱**（[draft_box.md](draft_box.md)）。注意：「保存到草稿」「存草稿」「先存着不发」等**必须明确识别到用户希望保存为草稿而非发送**才触发新建草稿，否则走发送流程。
- **「给 xxx 发邮件」「发一封邮件给 xxx」**（识别出具体发送时间则为预约发送，**未识别出一律立即发送**）→ 使用 **新建邮件**：立即发送见 [send.md](send.md)，预约发送见 [draft_box.md](draft_box.md) 场景七。

## 错误与异常

执行中遇错时，按下列**处理原则**执行；具体展示文案、更多场景及子技能错误分支见 [scripts_and_errors.md](scripts_and_errors.md) 及各子技能 reference 的「错误处理」小节。

| 场景 | 处理原则 |
|------|----------|
| 脚本非 0 退出或输出含 `error` | 展示脚本/接口返回的 error 信息，建议重试或登录 Web 邮箱处理 |
| 查找邮件返回 `beyond_half_year: true` | 按技能约定向用户提示半年限制，不自行改写文案 |
| **未获用户确认即发送（新建邮件/回复/转发）** | 新建邮件（send/create-draft）、回复（reply）、转发（forward）均须先展示预览并等待用户确认后才可执行；仅当用户明确表示「直接发/不用确认」时，才可在展示后跳过等待确认。 |
| 发送时某群组无权限（如 error 含「用户没有权限使用邮件组」） | 不得自行改选其他群组；直接提示该群组无权限或原文展示 error，由用户决定是否更换收件人 |
| 展示收件人/抄送人（来自 search-users） | 严格按 search-users 返回数据展示；优先姓名+工号，无时再用邮箱 E；禁止臆断、猜测、编造 |
| 时间或当前用户解析失败（get-time / my-info 失败或无输出） | 不猜测当前时间或当前用户；提示用户提供具体日期/时间或指定收件人，或检查环境 |
| 删除目标为历史邮件/归档邮件 | 明确告知「历史邮件/归档邮件不能删除」，不执行 delete-mails |
| 上下文无草稿列表但用户说「第 N 封」 | 提示用户先「查看草稿箱」获取列表 |
| 必填参数缺失、认证异常等 | 按 scripts_and_errors 中对应场景处理 |

其余场景（草稿序号超范围、参数缺失、认证异常等）→ [scripts_and_errors.md](scripts_and_errors.md)。各子技能细分错误 → 对应 reference 的「错误处理」（如 [summary.md](summary.md)、[outbox.md](outbox.md)、[search.md](search.md)、[view.md](view.md)、[attachment.md](attachment.md)、[folder.md](folder.md)、[reply.md](reply.md)、[forward.md](forward.md)）。

### 输出格式

- reference 里写了表头、列顺序、Markdown 结构的 → **按原文执行**，不改成「更易读」的别的样式。
- 列表/表格类（发件箱列表、收件箱筛选结果等）→ 用该 reference 规定的表头与列顺序。
- 无格式约定时 → 用简洁表格或分点列出时间、发件人、收件人、标题等；少废话。
