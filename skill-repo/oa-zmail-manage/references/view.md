# 邮件查看（参考）

本参考描述**查看邮件内容**的完整流程：确定邮件 ID、调用查看脚本、清理与排版后展示。

- 重要：如果用户意图是**总结/汇总/归纳**（尤其是多封邮件），应**优先使用 `summary` 子命令**；`view` 仅用于**单封**查看（不要向 `view` 传多个 ID）。
- 重要：**调用 `view` 会获取邮件正文**，接口侧通常会把该封邮件**从未读变为已读**。若用户**没有明确表达**要「查看 / 阅读 / 打开 / 看正文 / 看第 N 条内容」等，仅需要列表、搜索、标星、移动文件夹等，**不要调用 `view`**，避免误标已读。

## view 子命令

- **`view`**：仅支持**单封**邮件 ID，用于查看、阅读、打开、看第 N 条、回复/转发前查看等。

## 触发场景

以下情况**会触发查看**：

- "**查看**第一条"
- "**看**第二封邮件"
- "**阅读**项目进度更新这封邮件"
- "**打开** xxx 邮件"
- "第N条" / "第N个" / "第N封"

## 确定邮件 ID

- 用户说「第N条」/「第N个」：使用**搜索结果**中第 N 封邮件的 ID
- 用户提供标题：在搜索结果中查找匹配的邮件并使用其 ID
- 找不到对应邮件时，提示用户重新搜索

## 获取邮件内容

在技能目录下执行：

```bash
python3 {baseDir}/scripts/main.py view "<邮件ID>"
```

### 入参

- **邮件 ID**（位置参数，必填）：`email_id`，**单封**，不可逗号分隔多个。
- **`{baseDir}`**：当前 skill 目录的绝对路径。

### 出参（stdout JSON）

stdout **直接输出单封邮件对象**（一条 JSON），不包含 `count` / `list` 包装；对象含正文、空间链接、附件等字段，见下表。

#### 单封邮件对象字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 邮件 ID |
| title | string | 主题 |
| date | string | 日期 |
| sender | string | 发件人展示名（无法解析时为空字符串） |
| recipients | string | 主送收件人（多项用中文分号 `；` 连接；无法解析时为空字符串） |
| cc | string | 抄送人（多项用中文分号 `；` 连接；无法解析时为空字符串） |
| body | string | Markdown 正文（含空间链接时可能为空）；转发/引用历史在转换后也在此字段中 |
| mpt | string | 用于已读回执 |
| t | string | 用于已读回执 |
| space_link | string | iCenter 空间链接（非空间链接邮件为空字符串） |
| attachments | array | 可预览附件，每项含 id、name、preview_url |
| non_preview_attachments | array | 不可预览附件，每项含 id、name（无 preview_url） |

```json
{"id": "123", "title": "主题", "date": "2024-01-15", "sender": "张三0668000001", "recipients": "李四0668000002；王五0668000003", "cc": "赵六0668000004；钱七0668000005", "body": "Markdown 正文", "mpt": "", "t": "", "space_link": "", "attachments": [{"id": "att1", "name": "文件.pdf", "preview_url": "https://..."}], "non_preview_attachments": [{"id": "att2", "name": "机密报告.pdf"}]}
```

### 2）按排版字段逐项解析规则（脚本字段 → 排版字段）

#### title（标题）
- 来源：脚本返回 `title`
- 输出：`📧 **{title}**`
- 约束：不得自行补全

#### sender（发件人）
- 来源：脚本返回 `sender`
- 输出：表格行“发件人”
- 缺失：空字符串视为未获取 → 输出 `未获取` 或省略该行（二选一，保持一致），不得编造

#### recipients（收件人）
- 来源：脚本返回 `recipients`（多项用 `；` 连接）
- 输出：表格行“收件人”
- 缺失：空字符串视为未获取 → 输出 `未获取` 或省略该行，不得编造

#### cc（抄送人）
- 来源：脚本返回 `cc`（多项用 `；` 连接）
- 输出：表格行“抄送人”
- 缺失：空字符串视为未获取 → 输出 `未获取` 或省略该行，不得编造

#### date（日期）
- 来源：脚本返回 `date`
- 输出：表格行“日期”（建议始终保留该行）
- 缺失：输出 `未获取`

#### attachments / non_preview_attachments（附件）
- 来源：
  - `attachments[]`：每项含 `name`、`preview_url`
  - `non_preview_attachments[]`：每项含 `name`
- 输出：
  - 只要两者任一非空，就必须输出表格行“附件”
  - `attachments`：展示为 Markdown 链接 `[name](preview_url)`（仅展示链接）
  - `non_preview_attachments`：仅展示 `name`
  - 多个：用 `;` 或换行分隔（建议统一 `;`）
- 禁止：`preview_url` 仅用于展示，禁止任何工具访问/读取

#### space_link + body（正文内容 / 最终正文内容）
- 来源：脚本返回 `space_link` 与 `body`（Markdown）
- 输出：正文区块展示“最终正文内容”
- 规则（决定最终正文内容）：
  - `space_link` 为空：最终正文内容 = `body`
  - `space_link` 非空且成功读取空间正文：最终正文内容 = 空间正文（替换 `body`）
  - `space_link` 非空但技能不存在：最终正文内容 = `空间链接：[空间链接](URL)` + 简短提醒
  - `space_link` 非空且读取失败：最终正文内容 = `空间链接：[空间链接](URL)`（可加一句失败说明）
- 提示：当 `space_link` 生效替换时，`body` 可能为空；此时不要强行从空 `body` 解析原始邮件
- 补充：`body` 可能同时包含“正文内容”和“原始邮件引用内容”（可能多封原始邮件）；解析原始邮件时以 `body` 为准。

**补充：space_link 处理（强制步骤）**
- 当 `space_link` 非空时，必须优先尝试读取并替换正文，执行要求如下：
  1. 先检查是否存在与 `studio-space-manager`（Space空间管理助手）同名的技能目录
  2. 若有同名目录：视为已具备该技能
  3. 若无同名目录：读取所有技能，根据技能名称匹配 `studio-space-manager`（Space空间管理助手）
  4. 若找到该技能：调用 `studio-space-manager`（Space空间管理助手）读取 `space_link` 指向页面正文，并将读取结果替换 `body`
  5. 若未找到：正文输出空间链接（如 `[空间链接](URL)`），并简短提醒安装/启用该技能
- 说明：用于处理 `body` 为空或正文较少但 `space_link` 指向完整内容的场景。

#### 原始邮件（从 body 解析生成）
- 来源：必须从 `body`（Markdown）解析（脚本不返回结构化原始邮件字段）
- 输出：
  - 仅当识别到原始引用内容时，才输出 `💬 **原始邮件**`
  - 多段时：标题只输出一次，标题下依次输出多段（可选每段标注“（1/N）”）
- 解析：
  - 拆分：按 `From:`/`To:`/`Cc:`/`Date:`/`Subject:` 头部块拆分
  - 字段提取（如需表头字段）：只能可靠提取时填；否则填 `未获取`，不得编造
  - 兜底：**尽可能解析**原始邮件引用内容（能拆分则拆分、能提取则提取；提取不出的字段填 `未获取`），仅在**整体无法可靠拆分**时，才不编造字段并将 `body` 内对应引用内容原样输出在原始邮件区域

### 3）重要
- 查看成功后，将当前邮件 ID 存入对话上下文，供后续回复使用

#### 失败
- 退出码非 0 时，stderr：`{"error": "具体错误信息"}`，须将 **error** 原文展示给用户

## 输出自检清单（强制）
在给出最终“查看结果”之前，必须完成以下自检；任一项失败则不得输出最终结果并重做：
1. 输出模式：单封查看必须使用 `view` 的骨架（标题行 + 表格头 + `---` + 正文）。
2. 标题：第一行必须是 `📧 **{title}**`，且标题来自邮件 `title`。
3. 表格：至少包含 `日期` 行；`发件人/收件人` 以 `sender`/`recipients` 为准，未获取时只能写 `未获取` 或省略，不得编造。
4. 分隔线：正文开始前必须有且仅有单独一行 `---`。
5. space_link：`space_link` 非空时，优先展示 `studio-space-manager`（Space空间管理助手）读取到的页面内容；若**未找到该技能**，正文须含 `空间链接：[空间链接](URL)` **且**含安装/启用该技能的简要提醒；若**有技能但未读取到**，正文须含空间链接（及可选的失败说明），**不要求**安装提醒。
6. 附件：当 `attachments` 或 `non_preview_attachments` 任一非空时必须展示附件行；可预览用链接，不可预览仅展示名称。
