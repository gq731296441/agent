# 邮件回复（参考）

本参考描述**回复当前查看的邮件**的完整流程：获取邮件 ID 与回复内容、**回复前展示并等待用户确认或修改**、用户明确发送后再调用回复脚本、处理返回值。回复时默认不携带原邮件附件；如需携带附件可在调用脚本时加 `--with-attachments`。若需在回复中新增本地文件为附件请使用 Web 邮箱。

**强制要求（不可跳过）**：**必须先通过 `reply-brief` 获取标题和收件人，再展示回复预览（标题、收件人、抄送、密送、回复正文），等用户明确确认（如回复「确认发送」「发送」）后才能调用回复脚本。** 即使用户在一次消息中同时给出了回复对象和回复内容，也**不得直接发送**，必须先把回复预览展示给用户，等待用户说「确认发送」或「发送」后再执行发送；**严禁在未展示、未获用户确认的情况下直接调用回复脚本。** **未指定收件人时**：仅回复给原发件人，标题不可修改、收件人不可修改、不可增加抄送；**指定收件人/抄送/密送时**：收件人、抄送人、密送人**不能同时为空**，至少填一项；先通过 search-users 确认，调用 reply 时传入 `--to`/`--cc`/`--bcc`，可含收件人、抄送、密送。回复邮件**标题不可修改**，**仅可修改回复内容**。

**收件人展示规则**（与发邮件、查看邮件一致）：**优先使用姓名+工号，没有时再使用邮件地址**。有 N、UNO 时用「姓名（工号）」；无时用邮箱地址。

## 模型执行口径（必须遵守）

- 模型在处理“回复”意图时，必须先调用 `reply-brief` 获取预览基础信息。
- 若 `reply-brief` 返回 `notice`，模型必须在预览中原文展示该提醒（「该邮件已被设置为禁止转发，回复不能携带原文和附件」）。
- 用户未明确确认发送前，模型不得调用 `reply`。
- 用户要求改内容时，模型应重新生成并展示预览后再等待确认。

## 触发场景

以下情况**会触发回复**：

- "**回复**这封邮件，内容：收到，谢谢"
- "帮我**回复**一下，说已经知悉"
- "用以下内容**回复**：同意该方案"
- "**回复**邮件：明天开会讨论"

## 前置条件

1. **从上下文获取当前邮件 ID**：
   - 用户刚通过「查看」看过某封邮件，该邮件的 ID 应从对话上下文中取得。
   - **若上下文中没有可用的邮件 ID**：提示「当前没有查看的邮件」，建议用户先搜索或查看一封邮件后再回复，流程结束。

2. **从用户输入获取回复内容**：
   - 从「内容：xxx」「回复：xxx」或整段输入中解析回复正文。
   - **若用户未提供回复内容**：提示「请填写邮件内容」，流程结束。

3. **可选收件人/抄送/密送**：
   - **若用户指定了回复给谁、抄送谁、密送谁**：收件人、抄送人、密送人**不能同时为空**，至少填一项；须先按 [search-users.md](search-users.md) 确认收件人，调用 reply 时传入 `--to`/`--cc`/`--bcc`（逗号分隔邮箱，同 send/forward）。
   - **若用户未指定**：按默认逻辑，仅回复给原发件人，无需传 `--to`/`--cc`/`--bcc`。

## 回复前展示与确认（必须执行）

**在调用回复脚本之前**，必须完成以下步骤，**不得在未展示、未获用户确认的情况下直接发送**。

1. **获取原邮件摘要**
   通过 `reply-brief` 命令获取原邮件的标题和收件人：
   ```bash
   python3 {baseDir}/scripts/main.py reply-brief "<邮件ID>"
   ```

   **入参**：位置参数 **邮件 ID**（必填）。

   **出参（stdout JSON）**：
   - **成功**：`{"title": "...", "mt": [...]}`。`title` 为邮件主题（脚本侧已对「答复:」前缀做过处理）；`mt` 为原邮件收件人列表，每项为对象，常见字段含 **N**、**UNO**、**E**、**T** 等，以实际返回为准（与 search-users 用户项字段风格一致）。
   - **禁止转发提示（可选字段）**：当原邮件 `can_forward=false` 时，返回会额外包含 `notice`，示例：`{"title":"...","mt":[...],"notice":"该邮件已被设置为禁止转发，回复不能携带原文和附件"}`。收到该字段时，应在预览阶段原文提示给用户。
   - **失败**：stderr `{"error": "具体错误信息"}`，退出码非 0。

2. **组装回复预览信息**
   - **标题**：原标题已包含 `答复:` 前缀则直接使用，否则加上 `答复: `
   - **收件人**：未指定时来自 reply-brief 的 `mt`（原发件人）；指定时来自 search-users 确认的 to/cc/bcc。展示规则：有 N、UNO 时用「姓名（工号）」，无时用邮箱地址。
   - **回复内容**（用户填写的正文）
   - **是否携带原邮件附件**（**必须**：当根据上下文——如查看邮件结果中的附件信息——可判定原邮件有附件时，预览中须单独展示一行，写清本次回复是**带附件**还是**不带附件**）：未提及附件时默认**不带**原邮件附件（对应脚本不传 `--with-attachments`）；用户明确要求带附件时为**带**（对应传 `--with-attachments`）。
   - **禁止转发提醒**（可选）：若 `reply-brief` 返回了 `notice`，需在预览中同步提示该文案。

   > **重要**：回复邮件**标题不可修改**，**仅可修改回复内容**。未指定收件人时仅回复给原发件人；指定时以 `--to`/`--cc`/`--bcc` 为准。若用户要求修改标题，应说明回复不支持，建议使用「发邮件」功能。

3. **向用户展示**
   以简洁格式展示给用户，并**明确提示**仅可修改回复内容：

4. **等待用户回应**
   - 若用户回复「**确认发送**」「**发送**」「**发吧**」等**明确发送意图**：则进入下一步「调用回复脚本」执行发送。
   - 若用户要求**修改回复内容**：更新内容后**重新展示**回复预览，再次等待确认。
   - 若原邮件有附件且用户要求**改为带附件/不带附件**：更新**是否携带原邮件附件**一行后重新展示预览，再次等待确认。
   - 若用户要求修改标题：提示「回复邮件不支持修改标题，如需此类操作请使用发邮件功能。」
   - 仅当**明确识别到发送意图**后，才可调用回复脚本。

### 回复预览展示格式示例

```
**回复邮件预览**

**标题**：答复: 季度会议邀请
**收件人**：张三（0668000001）
**是否携带原邮件附件**：不带（默认；原邮件有附件时本行必填）
**回复内容**：
收到，我们会尽快处理。

请回复「**确认发送**」以发送，或告诉我需要修改的**回复内容**。
```

（单条预览里只要原文有附件，即须展示「是否携带原邮件附件」；原邮件**无**附件时可省略该行。）

## 调用回复脚本

**仅当用户已明确表示发送后**，在技能目录下执行：

**默认回复（仅回复给原发件人）**：
```bash
python3 {baseDir}/scripts/main.py reply "<邮件ID>" "<回复内容>" [--with-attachments]
```

**指定收件人/抄送/密送**：
```bash
python3 {baseDir}/scripts/main.py reply "<邮件ID>" "<回复内容>" [--to ...] [--cc ...] [--bcc ...]
```

- **{baseDir}**：当前 skill 目录的绝对路径。
- **邮件ID**（必填）：当前查看的邮件 ID，从上下文中获取。
- **回复内容**（必填）：用户填写的邮件正文；若包含空格、换行或特殊字符，需用引号包裹。
- **--with-attachments**（可选）：携带原邮件附件。
- **--to / --cc / --bcc**（可选）：不传则回复给原发件人；传则为逗号分隔邮箱（同 send/forward）。

## 根据返回值处理

- **成功**：退出码 0，stdout 为 `{"status": true, "mid": "<邮件ID>", "message": "..."}`。`mid` 仅用于后续操作/链路追踪，**不要展示给用户**；回复顺序为：先展示“邮件已经发送。”；再判断 `message`，有值则直接展示、无值则不展示；最后附 Web 邮箱链接。

- **失败**：退出码非 0，stderr 为 `{"status": false, "error": "异常信息"}`。将 **error** 原文展示给用户（脚本已在 error 末尾追加 Web 邮箱提示），建议检查网络或重试。参见 [scripts_and_errors.md](scripts_and_errors.md)。
