# 报告编写要点与检查规范（检查标准）

> 依据《周报月报编写会议纪要》（2026/10/19）整理。红线项（★）任一不满足即退回修改。

## 一、定位与心态（前提，红线）

| 要点 | 说明 |
|---|---|
| ★ 红线1：第一责任人意识 | 报告编写者是业务第一责任人（owner），对成败负首要责任，不能把自己当执行人；落实已共识的要求时该事项就是 top one，不能先入为主打折扣 |
| ★ 红线2：报告是工具不是业绩 | 报告是推动业务目标达成的手段；若对工作推进无帮助、投入产出比不划算，可砍掉报告，而不是为了发而发 |
| 报告是对外信息窗口 | 领导印象很大程度来自报告；软绵绵的措辞（"建议相关方…"）等于打折，打折到业务单位就推动不了 |
| 自信表达，虚心听取 | 先说结论再说解释；提问题时给领导做选择题（方案一/方案二），不能只抛问题 |

## 二、动笔前必答三问（检查时确认报告是否体现）

1. **读者是谁？** 读者放收件人（按优先级排序），知悉者放抄送人。
2. **读者想知道什么？** 不同人群关注点不同，逐人群梳理需求。
3. **我要传递什么？** 与定位无关的内容不写。

## 三、固定结构（铁律）

**第一部分：结论（1~3句话）→ 第二部分：风险问题及应对 → 第三部分：详细进展/基础数据**

| 要点 | 说明 |
|---|---|
| ★ 红线3：顺序铁律 | 先说问题风险，再说努力成果，不许先表功 |
| ★ 红线4：结论区不膨胀 | 结论仅1~3句话，重点工作写第二部分，不塞进结论区 |
| 结论放在最前 | 最重要的信息放前三句 |
| 风险部分固定存在 | 当月无风险写"无"；有风险必须有举措+责任人+闭环跟踪 |
| 次要内容折叠/后置 | 大表格、大图表、历史数据折叠；重要信息前置 |
| 信息辐射器 | 肯定业务单位贡献（at其领导）、推送好实践/新规定/小贴士 |

## 四、结论与表达规范

| 要点 | 红线/注意 |
|---|---|
| ★ 红线5：结论必须无二义性 | 不能只罗列数字；"比例偏高"不是结论，"比例X%，超出目标Y%，必须整改"才是结论。敢写观点，否则不要写 |
| ★ 红线6：好/坏必须说清 | 必须明确"正常/不正常、达标/超标"；"未达成"若实为"已超标"必须写清 |
| 时间与范围限定 | 累计数据写"截至X日、全年累计"；统计范围（含/不含分摊）明确 |
| 变化体现业务价值 | 写"为配合XX业务调整，顺利完成XX"，不喊口号式空结论 |
| 避免弱语气词 | 不用"概述"等弱语气词，直接列1、2、3 |
| 弱项不遮掩 | 领导给的更高要求必须传递，不能只对照较低标准说"正常" |

## 五、标题、表格与数据规范

| 要点 | 说明 |
|---|---|
| ★ 红线7：文要对题 | 标题匹配报告实际范围，简洁明确；禁用"一览表"等无信息量标题 |
| 图表必配结论 | 表/图上方或旁边必须写结论，不能只怼一张表 |
| 数据排序 | 按重要程度排：异常/冗余率高的放前面、重点单位置顶 |
| 视觉凸显 | 颜色、箭头、图标凸显数据好坏与趋势 |
| ★ 红线8：数据标注来源与时间节点 | 标注数据来源+统计截止时间 |
| 挤掉水分 | 分摊等非可控因素预估后刨除，设纯用量内控目标，统计规则补充说明 |

## 六、任务跟踪表规范（如有任务表则检查）

| 要点 | 红线/注意 |
|---|---|
| ★ 红线9：任务定义四要素 | 时间+第一责任人+完成事项+验收标准，缺一不可；目标≠任务，目标分解出的可度量行动才是任务 |
| ★ 红线10：不写"推进人" | 写"第一责任人"，协作方写"参与人"；离职/离岗人员任务直接替换 |
| 完成时间 | 写"计划完成时间"；增加状态标识（红/黄/绿灯），绿灯可折叠 |
| 已完成任务 | 折叠或删除 |
| 历史进展 | 最新进展显示化+时间标注，历史进展折叠 |
| 跟踪范围 | 明确跟踪全年任务还是当前重点任务，不全部怼进一份报告 |

## 七、报告体系与频度定位

| 要点 | 说明 |
|---|---|
| ★ 红线11：双周报聚焦问题跟踪 | 双周报就跟踪问题，不罗列详细进展；现状数据作附录折叠 |
| 报告间分工 | 日报/周报/月报各司其职，信息不重复轰炸 |
| 分发策略 | 思考一份报告满足所有读者，还是按人群分开发送 |

## 八、发送与沟通纪律（红线）

| 要点 | 红线/注意 |
|---|---|
| ★ 红线12：异常先行告知 | 异常/敏感内容先告知科长、部长，认可后再发；口径一致对外 |
| ★ 红线13：只认书面结论 | 重要事项须领导书面确认，不认口头说法 |
| 问题要有行动 | 报问题前已有沟通/跟踪动作，不能光报问题不推动 |
| 责任人明确 | 问题点名（at到人），写清希望谁解决 |

## 九、发送前检查清单

**结构检查**
- [ ] 三问已回答：读者是谁/读者想知什么/我要传递什么
- [ ] 结构为"结论→风险问题及应对→详细进展"固定三段
- [ ] 结论区仅1~3句话，未塞入正文内容
- [ ] 风险部分存在（无则写"无"），每条风险有举措+责任人+闭环
- [ ] 问题风险在表功内容之前

**内容检查**
- [ ] 每条结论明确表达观点，无二义性，好/坏、达标/超标说清
- [ ] 关键数值写明与目标的差距，未用模糊词
- [ ] 累计数据标注"截至X日/全年累计"，统计范围明确
- [ ] 数据标注来源+时间节点
- [ ] 变化描述体现业务支撑价值，无口号式空结论
- [ ] 无"概述"等弱语气词汇

**读者与呈现检查**
- [ ] 标题简洁、文对题，章节标题有信息量
- [ ] 收件人=读者（已排序），抄送人=知悉者
- [ ] 图表上方有结论，重点数据用颜色/箭头/图标凸显
- [ ] 表格按重要度排序，重点关注内容前置
- [ ] 大表/图表/历史数据已折叠

**任务表检查**（如有）
- [ ] 每项任务含时间+第一责任人+事项+验收标准
- [ ] 无"推进人"表述；无离职人员；已完成任务折叠/删除；有状态标识

**发送纪律检查**
- [ ] 异常/敏感内容已提前告知科长、部长并获认可
- [ ] 重要结论已有书面确认，未依赖口头承诺
- [ ] 报告发出前已与审核领导确认，口径一致

## 判定规则

- 任一红线项 ❌ → 需退回重写
- 无红线违规但存在 ❌ → 修改后可发
- 全部符合或仅有 ⚠️ → 合格可发
- 发送纪律项无法从文本判断 → 标记"待发送前人工确认"
