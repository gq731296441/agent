# 故障排查指南

## 快速诊断决策树

```
问题开始
  │
  ├─→ 无法运行技能
  │    ├─ 检查 Python 版本 >= 3.8（推荐 3.11；3.7 及以下无法运行）
  │    ├─ 检查依赖库：pip install -r requirements.txt
  │    ├─ 检查配置文件语法（YAML 格式，assets/config/default_config.yaml）
  │    └─ 检查文件权限
  │
  ├─→ 表头验证失败
  │    ├─ 使用官方模板文件
  │    ├─ 检查 Excel 列名是否完全匹配 13 个必需列
  │    ├─ 检查是否有隐藏的空列
  │    └─ 确认数据位于【软件结构】sheet（不是其他 sheet）
  │
  ├─→ 出现"回退为智能选择"警告
  │    ├─ 说明文件可能未使用标准模板（无"软件结构"sheet）
  │    ├─ 确认检查对象是否正确
  │    └─ 建议使用官方模板重新生成
  │
  ├─→ 所有行 API 调用失败
  │    ├─ 检查网络连通性与代理设置（10.57.153.195:8080）
  │    ├─ 检查认证环境变量：
  │    │    $ echo $coclaw_empno $coclaw_token
  │    │    （或 RDC_EMP_NO / RDC_AUTH_TOKEN / X_Emp-No / X_Auth-Value）
  │    └─ 确认 Token 未过期
  │
  ├─→ 部分行验证失败（必填字段缺失）
  │    ├─ 检查"层次""部件类别"是否全部填写
  │    ├─ 检查"部件类别"枚举值是否正确
  │    └─ 对于空部件编号的常规组件，
  │         检查同行的"中文名称""英文名称""英文代号"是否填写
  │
  ├─→ query 无匹配结果
  │    ├─ 确认目标行"部件编号"为空（否则不会查询）
  │    ├─ 检查中文名称/英文名称/英文代号是否填写完整
  │    ├─ 确认认证环境变量已设置
  │    └─ 尝试放宽查询条件（多条件无结果时会降级为单条件）
  │
  ├─→ backfill 被阻止
  │    ├─ 确认序号在查询结果文件中存在（missing_ids）
  │    ├─ 确认序号对应部件编号非空（empty_partno）
  │    ├─ 同一源行多个不同部件编号时只选一个（conflict）
  │    └─ 冲突时可按第一级基准自动筛选
  │
  ├─→ 处理速度慢
  │    ├─ 大量 API 调用耗时较长属正常现象
  │    ├─ 建议分批处理大型文件
  │    └─ 确认日志中 API 是否频繁失败重试（3 次退避）
  │
  └─→ 内存不足
       ├─ 分批处理大型 Excel 文件
       ├─ 减少并发处理数量
       └─ 增加系统内存
```

## 常见问题 (FAQ)

### Q1: "未找到目标工作表'软件结构'，回退为智能选择" 警告
**可能原因**:
- Excel 文件中的工作表不包含名为"软件结构"的 sheet
- 使用了非标准模板

**处理**:
1. 打开 Excel 文件，确认组件清单数据在哪个 sheet
2. 若数据确实在"软件结构"sheet，检查 sheet 名是否完全一致（含空格）
3. 建议使用官方模板重新创建文件

### Q2: API 调用失败/所有部件都"不存在"
**可能原因**:
- 认证环境变量未设置（`coclaw_empno` / `coclaw_token` 或等价别名）
- Token 已过期
- 网络不可达（10.57.153.195:8080 内网服务）

**检查**:
```bash
echo "EmpNo: $coclaw_empno"
echo "Token: $coclaw_token"
```

**解决**:
- 重新获取有效 Token（通常需要登录企业门户）
- 确认处于内网环境（10.57.153.195 为内网地址）

### Q3: validate 报"文档格式检查不通过"且跳过数据库校验
这是**正常设计**：当格式检查不通过（非"未提供文档编号"）时，addDir 部分会跳过
PDM 编号/代码库/路径校验。请根据"检查详情"修正模板问题后重跑。

### Q4: 为什么外部第三方组件的部件编号必须填写？
外部组件的所有信息（中文名、英文名等）存储在第三方组件库（iComp）中，必须通过部件编号查询。
不填写则无法验证该组件是否有效、是否为废弃状态。

### Q5: 某部件在 PDM 中存在，但提示"生命周期状态非审批完成"
常规部件的生命周期状态必须为"审批完成"才能通过校验。请：
1. 联系 PDM 管理员确认部件状态
2. 等待审批完成后重新校验

### Q6: 部件编号为空时，没有 API 验证，对吗？
是的。部件编号为空时无法在系统中查询验证，仅检查字段完整性（中文名称/英文名称/英文代号必填）。
如需验证，应先申请部件编号。

### Q7: query 报告中的"序号"和"源行号"有什么区别？
- `源行号`：原始 Excel 中的实际行号
- `序号`：查询结果中全局唯一的递增编号，用于 `backfill --result-ids` 精确选择

同一源行可能对应多个 `序号`（多匹配），回填时通过 `序号` 选择要回填的候选。

### Q8: backfill 提示"回填冲突"如何处理？
同一源行查询到多个不同部件编号时：
1. 若恰好 1 个候选与第一级部件基准（产品/项目）一致，会自动选中（提示"已按基准自动匹配"）
2. 否则需人工在提示的各候选（含产品/项目信息）中选择一个 `序号` 重新执行

### Q9: backfill 提示"仍有未覆盖的空行"？
说明原始文件中还有部件编号为空的行未被选中的序号覆盖。这些行保持为空，
如需全部回填，可补充对应的 `序号` 再次执行。

### Q10: 如何禁用 Gerrit 路径校验？
```bash
python main.py validate 组件清单.xlsx --no-path-check
```
独立运行 addDir 脚本时可用环境变量 `ENABLE_PATH_CHECK=false`。

### Q11: 日志在哪里？如何查看详细执行过程？
日志输出到控制台，同时记录到 `./logs/` 目录：
```bash
tail -f logs/yx_sw_component_manager_*.log
grep -i error logs/*.log
```
可用 `--log-level DEBUG` 查看详细 API 请求/响应。

### Q12: 临时文件占用太多空间？
运行期会生成日志（`./logs/`）与埋点缓存（`.skill_usage_cache/`），均可手动清理：
- `rm -rf logs/ .skill_usage_cache/`

### Q13: Python 版本要求？
**Python 3.8 及以上**（推荐 3.11）。代码使用了 `dataclasses` 与内建泛型注解，
且部分依赖（如 `numpy>=1.21`）不再支持旧版本 Python。Python 3.7 及以下无法运行。

## 日志级别说明

| 级别 | 内容 | 何时使用 |
|------|------|----------|
| DEBUG | 详细 API 请求/响应、Excel 单元格值 | 调试时 |
| INFO | 工作表选择、校验进度、结果摘要 | 默认 |
| WARNING | API 重试、部件状态警告、认证缺失 | 默认 |
| ERROR | 校验失败、API 错误、任务异常 | 默认 |
