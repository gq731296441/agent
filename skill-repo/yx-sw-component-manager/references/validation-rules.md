# 验证规则详细说明

## 验证流程总览

`validate` 子命令的 wx 逐行规则引擎按以下流程执行（见 `scripts/validators/rule_engine.py`）：

```
┌─────────────────────────────────────────────┐
│  1. 加载 Excel，优先选择【软件结构】sheet     │
│     （不存在时回退智能选择并告警）             │
└──────────────────────────┬──────────────────┘
                           ▼
┌─────────────────────────────────────────────┐
│  2. 表头验证（Header Validation）            │
│     • 检查 13 个必需列是否齐全               │
│     • 缺少必需列 → 终止处理                  │
└──────────────────────────┬──────────────────┘
                           ▼
┌─────────────────────────────────────────────┐
│  3. 逐行规则引擎校验（11 条规则）            │
│     • 层次栈维护（用于层次关系检查）          │
│     • 逐行执行所有规则，收集错误与修正建议    │
└──────────────────────────┬──────────────────┘
                           ▼
┌─────────────────────────────────────────────┐
│  4. API 一致性检查（不自动修正，仅生成建议） │
│     • 外部第三方组件 → iComp API             │
│     • 常规部件（编号非空）→ PDM 部件 API     │
└──────────────────────────┬──────────────────┘
                           ▼
┌─────────────────────────────────────────────┐
│  5. addDir 校验（格式/编号/代码库/路径）     │
│     • 见「addDir 校验流程」章节              │
└──────────────────────────┬──────────────────┘
                           ▼
┌─────────────────────────────────────────────┐
│  6. 生成统一审核报告（Excel/HTML/JSON）      │
└─────────────────────────────────────────────┘
```

## 规则引擎 11 条规则（wx）

`RuleEngine._register_default_rules()` 按以下顺序注册 11 条规则。
每条规则返回 `passed` / `message` / `suggested_value` / `field` / `current_value` / `row` 等字段。
`row = row_index + 2`（表头在第 1 行，数据从第 2 行开始）。

### 规则 1：必填字段检查（required_fields）

- **触发条件**: 所有行
- **检查内容**: `层次`、`部件类别` 是否为空（`None`/`NaN`/空字符串视为空）
- **失败**: 标记 `required_fields` 错误，不可自动修复，该行验证失败

### 规则 2：外部第三方组件部件编号要求（external_component_requirement）

- **触发条件**: `部件类别` = "外部第三方组件"
- **检查内容**: `部件编号` 必须填写
- **失败**: 标记错误，提示"外部第三方组件必须填写部件编号"

### 规则 3：第一行层次检查（first_row_level）

- **触发条件**: 仅第一行（索引 0）
- **检查内容**: 第一行 `层次` 必须为 0（根节点）
- **失败处理**:
  - 层次为空 → 错误，`suggested_value=0`
  - 层次不为 0 → 标记 `warning`（`warning: True`），`suggested_value=0`

### 规则 4：部件类别枚举验证（component_category）

- **触发条件**: 所有行（类别非空时）
- **检查内容**: `部件类别` 必须在以下 6 个值内：
  - 系统 / 软件 / 软件子系统 / 软件模块 / 组件 / 外部第三方组件
- **失败**: 标记错误，提示有效值列表

### 规则 5：层次断层检查（level_gap）

- **触发条件**: 层次有效且有前序层次
- **检查内容**: 当前层次与前序层次差值 `diff > 1` 视为断层
- **失败**: 标记错误，`suggested_value` 为 `层次应不大于{prev_level+1}`

### 规则 6：系统部件下层硬件类检查（system_hardware_check）

- **触发条件**: `部件类别` = "系统"
- **检查内容**: 该"系统"子树下（层次大于当前且未离开子树）是否存在不在允许列表
  （系统/软件/软件子系统/软件模块/外部第三方组件）中的部件类别
- **失败**: 标记错误，提示"该'系统'部件下层已有硬件类部件，禁止将'系统'按软件组件模式进行导入"

### 规则 7：外部第三方组件详细检查（external_component_detailed）

- **触发条件**: `部件类别` = "外部第三方组件" 且部件编号非空
- **检查内容**:
  1. 不允许维护下层部件（后续行存在层次更大的行）
  2. `层次` 禁止为 0（不能作为顶层部件）
  3. 调用 iComp API 校验部件编号存在性
  4. 组件状态不能为"废弃"
  5. 中文名称/英文名称/英文代号与 API 返回（`name` 字段）一致性
- **失败**: 按具体原因标记错误（不存在/废弃/不一致/API 异常）

### 规则 8：维护下层检查（subordinate_maintenance）

- **触发条件**: `部件类别` = "外部第三方组件" 或 `部件状态` = "失效"
- **检查内容**: 这些禁止维护下层的部件是否存在下层
- **失败**: 标记错误，提示"不允许维护下层部件"

### 规则 9：常规组件详细检查（normal_component_detailed）

- **触发条件**: `部件类别` ≠ "外部第三方组件" 且部件编号非空
- **检查内容**:
  1. 调用 PDM 部件 API 校验部件编号存在性
  2. 生命周期状态必须为"审批完成"
  3. 部件类别/中文名称/英文名称/英文代号与 PDM 返回（`PART_TYPE`/`NAME_CN`/`NAME_EN`/`EN_CODE`）一致性
- **失败**: 按具体原因标记错误（不存在/状态不对/不一致/API 异常）

> 注：部件编号为空时常规组件的"中文名称/英文名称/英文代号"必填检查由规则引擎外的
> `consistency_checker`/字段验证逻辑覆盖（见 `field-specification.md`）。

### 规则 10：跨产品一致性检查（product_consistency）

- **触发条件**: 用户提供 `--product-model` 且部件编号非空
- **检查内容**: 调用 PDM API 获取 `PRODUCT_MODEL`、`TEAM1_NAME`、`TEAM2_NAME`、`TEAM3_NAME`，
  与用户传入的产品规格型号/工作组类 1/2/3 对比
- **失败处理**:
  - 存在不匹配且**维护了下层** → 标记错误，提示"禁止对其维护下层"
  - 存在不匹配但**未维护下层** → 视为通过（允许导入，仅记录提示）
- **说明**: 未提供 `--product-model` 时跳过此规则

### 规则 11：名称首位字符检查（name_first_char）

- **触发条件**: 所有行（对应名称非空时）
- **检查内容**:
  1. 中文名称首位不能是符号
  2. 英文名称首位不能是符号，且不能包含中文
  3. 英文代号首位不能是符号，且不能包含中文
- **失败**: 标记错误，给出修正建议

## API 一致性检查（不自动修正）

在规则引擎逐行校验之后（`runner.run_row_rules`），对每行做 API 一致性检查：

1. `部件类别` = "外部第三方组件" 且编号非空 → 调 `ComponentAPIClient.search_component`
2. 否则（常规部件）且编号非空 → 调 `PartAPIClient.query_part`
3. 有返回且与 Excel 不一致 → 生成**修正建议**（`correction_suggestions`），**不自动写入 Excel**
4. API 无返回 → 记录 `api_no_result` 错误
5. API 异常 → 记录 `api_exception` 错误，继续下一行

## addDir 校验流程

`validate` 的 addDir 部分（`scripts/validate/db_and_path_check.py`）单独执行：

1. **文档格式检查**：
   - 从文件名提取前 12 位数字作为文档编号；编号存在时调 PDM 文档接口查询（`doc_detail`/`doc_info`）
   - 检查"软件结构"sheet 是否存在、最新模板关键列是否齐全、层次为空、缺软件模块/组件、代码库/目录未填等
2. **PDM 编号校验**：仅对"组件"和"软件模块"类别，批量调 `/v1/pdm/verify_part` 校验部件编号存在性
3. **代码库拆分校验**：调 `/v1/gerrit/split_repo_path` 拆分"代码库/目录"为 repo+path，
   再调 `/v1/gerrit/check_repo` 批量校验代码库存在性
4. **代码路径校验**：调 `/v1/gerrit/check_path` 校验路径在代码库中真实存在（可用 `--no-path-check` 跳过）
5. **测试/UT/FT 代码目录校验**：对"组件对应的测试代码目录/UT代码目录/FT代码目录"列执行与代码库相同的拆分+校验
6. **格式检查不通过**（非"未提供文档编号"）时，跳过数据库校验

## 错误分类汇总

### 致命错误（导致行失败）
| 规则/错误类型 | 描述 | 是否可自动修复 |
|--------------|------|----------------|
| `required_fields` | 必填字段（层次/部件类别）为空 | 否 |
| `component_category` | 部件类别值无效 | 否 |
| `external_component_requirement` | 外部组件缺少部件编号 | 否 |
| `level_gap` | 层次关系断层 | 否 |
| `system_hardware_check` | 系统下层含硬件类部件 | 否 |
| `external_component_detailed` | 外部组件不存在/废弃/不一致/有下层/层次为0 | 否 |
| `subordinate_maintenance` | 禁止维护下层的部件维护了下层 | 否 |
| `normal_component_detailed` | 常规部件不存在/未审批完成/不一致 | 否 |
| `product_consistency` | 跨产品不一致且维护下层 | 否 |
| `name_first_char` | 名称首位为符号/英文名称含中文 | 否 |

### 警告（不影响验证通过）
| 规则/警告类型 | 描述 | 是否自动处理 |
|--------------|------|--------------|
| `first_row_level` | 第一行层次不为 0 | 仅记录警告（已禁用自动修正） |
| `api_exception` | API 调用异常 | 否（记录并继续） |
| `normal_component_detailed`（warning） | API 客户端初始化失败/API 查询异常 | 否 |

## 规则优先级

- 单行只要有任一非 warning 规则失败，该行标记为"失败"
- 警告不影响"失败"状态，但会记录到警告列表
- `validate_row` 返回 `(passed, failed)`，其中 `passed = 全部规则通过 且 无致命错误`

## 验证结果判断

- **通过 (Passed)** = 无致命错误
- **失败 (Failed)** = 存在至少一个致命错误
- 统一报告的 `overall_status`：任一校验类型有"不通过"即整体"不通过"

## 扩展规则

规则引擎支持自定义规则（`Rule` 基类 + `register_rule`）：

```python
from scripts.validators.rule_engine import Rule, RuleEngine

class CustomRule(Rule):
    def evaluate(self, row_data, row_index, context=None):
        # 返回 {'rule': name, 'passed': bool, 'message': ..., 'suggested_value': ...}
        ...

engine = RuleEngine()
engine.register_rule(CustomRule("my_rule", "我的自定义规则"))
```
