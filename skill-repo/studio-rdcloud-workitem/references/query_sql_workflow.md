# 查询：条件格式与解析流程


> **工具约束（必遵）**：须通过本技能已有 `scripts/` 脚本执行研发云工作项能力；**禁止**使用 write、edit、web-search、web_fetch 等处理本业务或替代脚本；**禁止**新建 Python 脚本。

查询脚本已改为使用 **--select-items**（查询列）与 **--conditions**（查询条件），不再使用 --sql。**解析出的工作区、工作项类型均作为 --conditions 的一部分**，与其它筛选条件一起传入；工作区仍由脚本从配置或最近访问解析以确定查询目标。
结果展示约束：默认不得总结、省略或改写查询结果；仅当用户语义明确要求“总结/汇总/精简”时，才可在完整结果后追加总结。
结果展示约束：默认不得总结、省略或改写脚本返回结果；仅当用户语义明确要求“总结/汇总/精简”时，才可在完整结果后追加总结。

**脚本命令行调用与参数说明**：见 [query_work_item.md](query_work_item.md)（通用查询）、[query_my_work_item.md](query_my_work_item.md)（与我相关）。

## 1. --select-items 与 --conditions 格式

- **--select-items**：查询列，英文逗号分隔的字段名称，如 `标题,状态,标识`；不传则使用默认列（标识、标题、状态、工作项类型、更新时间）。
- **--conditions**：**条件组合**（不含 "where " 前缀）。**工作区、工作项类型与状态/标题等均写入此处**。支持：
  - **工作区、工作项类型**：从用户表述解析出的「在 XX 工作区」「查 XX 类型」须写入条件（与其它条件用 AND 等组合）。
  - **AND / OR**：多条件用 `AND`、`OR` 连接。
  - **括号 `()`**：分组与嵌套，改变优先级。
  - 字段名由脚本内部通过接口按名称解析。

**简单示例**

- `--select-items "标题,状态"` `--conditions "标题 like 测试"`
- `--select-items "标识,标题"` `--conditions "状态=进行中 AND 指派给=@me"`
- 仅查列、无条件：`--select-items "标题,状态"`（不传 --conditions）

**复杂条件组合与嵌套示例**

| 场景 | --conditions 示例 |
|------|--------------------|
| 工作项类型 + 工作区 | `工作项类型=用户故事 AND 工作区=业务运营` |
| 工作项类型 + 条件 | `工作项类型=任务 AND 状态=进行中` |
| 多条件 AND | `状态=进行中 AND 标题 like 测试` |
| 多条件 OR | `状态=进行中 OR 状态=待处理` |
| 括号分组 (OR 再 AND) | `(状态=进行中 OR 状态=待处理) AND 优先级=P0` |
| 括号分组 (AND 再 OR) | `(状态=进行中 AND 指派给=@me) OR (状态=待处理 AND 优先级=P0)` |
| 多层嵌套 | `(状态=进行中 OR (状态=待处理 AND 优先级=P0)) AND 标题 like 需求` |

**--order-by**：排序，格式为「字段名 asc/desc」或「字段1 asc, 字段2 desc」，如 `更新时间 desc`、`标题 asc, 状态 desc`；不传则默认按更新时间倒序。

**--limit**：返回/导出/参与统计的条数上限；列表类查询（通用/与我相关）最大 **10000**（超过按 10000），不传默认 **20**；导出为导出条数上限（不传则按脚本默认分页，且单页不超过 10000），统计为参与统计的条数上限（最大 10000；不传则脚本内约 3000 条内参与统计）。

## 2. 工作区解析

查询脚本**不再单独接收**工作区/工作项类型参数；**解析出的工作区、工作项类型均作为 --conditions 的一部分**传入。工作区由脚本内部从 `assets/config.json` 的 `api.workspace` 或「最近访问工作区」接口解析以确定查询目标；**query_my_work_item.py** 固定使用 SYSMySpace。

---

## 3. 解析与调用顺序

1. **解析查询列**：将 --select-items 拆成字段名列表；不传则用默认列。
2. **解析条件**：将 --conditions 解析为 sourceClauses；不传则无过滤。
3. **解析字段**：调用字段列表接口，将 select/conditions 中的**字段名称**解析为接口所需格式；0 条或多条匹配 → 终止并提示用户补充更明确字段。
4. **组装并调用查询 API**：用解析结果组装请求；失败 → 终止并输出错误。

任一步失败或无法唯一解析则立即终止，不执行后续步骤。

---

## 4. 字段列表接口（select / where 字段解析）

- **作用**：将用户输入的中文/英文字段名（即 SQL 中的字段名称）在脚本内部解析为接口所需格式。
- **请求**：由脚本通过 `rdcloud_api` 调用工作区字段列表接口（workspace 由工作区解析得到）。
- **规则**：用户字段名与接口返回的字段名称匹配；唯一则用该项；多项或未匹配时终止并提示用户补充更明确字段。

---

## 5. 工作项类型解析（作为 conditions 的一部分）

- **入参形式**：解析出的工作项类型作为 **--conditions** 的一部分传入（如 `工作项类型=任务 AND 状态=进行中`），脚本内部从 conditions 中解析工作项类型相关条件并转为接口所需类型标识。
- **何时生效**：当 --conditions 中包含工作项类型（如「工作项类型=任务」）时，脚本解析该条件并用于查询过滤；未包含则不按类型过滤。
- **脚本内部**：由脚本通过 `rdcloud_api` 调用工作项类型接口，将类型名称解析为 key；解析结果用于组装 queryCondition。

---

## 6. WHERE 条件解析

- **逻辑**：支持 AND、OR；条件按出现顺序组合；字段名通过同一字段列表接口按名称解析。
- **操作符**：`=`、`=_accurate`、`like`、`not like`、`!=`、`>`、`>=`、`<`、`<=`、`in`、`not in`、`is null`、`is not null`、`between`、`not between`。
- **特殊值**：`@Me` 表示当前用户；`@Today-365d` 等按约定处理。
- **高级数据字段**：所属产品、发布版本、所属项目等默认用 **like** 组装，避免精确匹配无结果。
- 条件组装为 `queryCondition.sourceClauses`，由脚本内部按字段名称解析后填入。

---

## 7. 失败与终止

| 步骤 | 失败/歧义 | 处理 |
|------|-----------|------|
| SQL 解析 | 无法拆成 select/from/where | 终止，报格式错误 |
| 字段解析 | 0 条或多条匹配 | 终止，并提示用户补充更明确字段 |
| 表名解析 | from 为 `*` 或空 | 跳过，不按类型过滤 |
| 表名解析 | 非唯一或未返回 | 终止，并提示用户补充更明确类型 |
| 接口调用 | HTTP/业务失败 | 终止，输出错误 |
| 查询 API | 请求失败或错误响应 | 终止，输出错误 |

## 常用字段名称（示例）

SQL 中一律使用**字段名称**（如 标题、状态、标识、指派给、处理人）。脚本内部通过 API 按名称解析，各工作区/类型以实际为准。常见名称：标识、标题、状态、工作项类型、更新时间、创建时间、指派给、处理人、优先级、描述、迭代、团队等。
