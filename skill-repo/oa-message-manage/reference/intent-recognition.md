### 批量操作目标群条件识别

当用户是在执行**批量删除群**或**批量退出群聊**，且没有直接提供群 URI，而是提供筛选条件时，先读取 `reference/group-management-search-group-list.md` 并调用 `scripts/search_group_list.py` 查询候选群。

可识别的筛选条件包括：

- `groupName`：群名称关键字，例如「群名里带开发推动」
- `adminID`：群主工号，例如「群主是 10145777」
- `lastmsgstamp`：最后消息时间阈值，用户侧应表达为相对时间，例如「最近 30 天没有消息」「近 1 年没动静」，脚本内部再自动换算
- `hasGroupName`：是否有正式群名，例如「没有正式名称的群」「有正式群名的群」

组合示例：

- 例如用户说「帮我找出近 1 年没动静、群主是 `10145777`、并且有正式群名的群」时，应映射为：`python {baseDir}/scripts/search_group_list.py --inactive-years 1 --adminid "10145777" --has-group-name 1`

常见业务口语说法示例：

- 「找出最近没动静的群」：优先映射到 `inactive-days` 或 `inactive-years`
- 「把王某某名下有群名的群找出来」：优先映射到 `adminID + hasGroupName=1`
- 「把群名里带开发推动、最近没消息的群筛出来」：优先映射到 `groupName + inactive-days`
- 「查一下没有正式群名、而且群主是 10145777 的群」：优先映射到 `adminID + hasGroupName=0`
- 「把那些长期没消息、我后面准备批量退掉的群先找出来」：先识别为条件查询，时间条件优先转成 `inactive-days` 或 `inactive-years`，再进入批量退出流程
- 「把这些符合条件的群先筛出来，我要批量解散」：先识别为条件查询，再进入批量删除流程

查询出候选群后，再进入对应批量操作文档执行二次确认和正式操作。

识别到操作类型后，按 `skill.md` 中"群管理流程"导航加载对应子任务文档执行。

其中“最近群查询”需要进一步识别模式：
- 提到“给我发送消息/收到消息” → `mode=recv`
- 提到“@我/艾特我” → `mode=atMe`
- 提到“看过/进入过/浏览过” → `mode=enter`
